# Safeword

Choose the workflow from the requested behavior before making production edits.
Follow any workflow the user explicitly requests.

- **Feature:** New state or distinct user actions, including in-memory state and one-file changes. Invoke `safeword:bdd` now. Resume the active feature ticket at its recorded phase, or create a feature ticket at intake and open the skill's DISCOVERY.md. Draft concrete Given/When/Then scenarios for the main actions and a failure case before editing production code. Then follow the BDD skill's planning and build steps.
- **Task:** A bug or one behavior change in an existing flow. Reproduce the behavior with a failing regression test, fix it, and rerun that test.
- **Patch:** A specified mechanical edit. Make the narrow change and run a quick check.

Resolve material scope decisions with the user. Follow the project's instructions and verify the result.
