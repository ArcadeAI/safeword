## Root cause descriptions

- **Other long-tail issues** — These are isolated design gaps, code-quality notes and one-off defects that don't share a fix with the larger causes. Examples include memoization, schema typing, monitor error isolation, canary submissions, Linear connector limits and miscellaneous skill workflow gaps. They are best handled individually as they arise.
- **Long-running and async operations give no progress, liveness or blocking wait** — Several commands run long or detached work silently and then require callers to poll status by hand: closeout cleanup and preview, retro extraction, apply revalidation, the verify and acceptance lanes, and async reviews. Pending states are often reported as action_required with nonzero exit codes, and sometimes no id or JSON envelope is emitted at all. A shared progress/heartbeat mechanism, plus a blocking wait mode and a distinct pending state, would make healthy work distinguishable from hangs.
- **Derived surfaces built by ad-hoc, hand-listed generators with no single regenerate-and-check** — Templates are copied into dogfood mirrors, Claude and Codex plugin bundles, catalogues and hashed fixtures by several independent scripts. Those scripts have implicit ordering, hardcoded file lists, unanchored path rewriting, exact Bun pins resolved through ambient PATH, and no local freshness check. The result is drift caught only in CI, merge conflicts in committed outputs, and shipped bundles that omit templates, hooks or guides the runtime needs. One manifest-driven pipeline with a single regenerate and fast check command, validated against runtime consumers, would remove both the toil and the packaging defects.
- **Gate requirements discoverable only by failing, with unactionable block messages** — Phase gates, ledger guards, ticket flag rules and phase_anchors conventions are enforced reactively at transition, commit or Stop time. Skills, templates and help text don't document them beforehand. Messages often stop at the first failure, use internal jargon, or name host-specific tools. Surfacing each prerequisite at scaffold or skill time, and making block messages aggregate all failures, name the remedy and the accepted format, and adapt to the host would remove the trial-and-error loops.
- **Plugin runtime identity pinned to versioned cache paths and session-start loading** — Skill paths, recovery commands, approval rules and activation markers embed a specific plugin cache version. That version is replaced mid-session, and Codex loads hooks only at startup. The integrity scan also treats host-owned lease and temp files as tampering and fails closed on every tool, including the repair tools. Version-independent entrypoints, semver-tolerant comparison, refreshed activation proof, and an integrity allowlist for host files with a repair exemption would stop the stale paths, the unverified warnings and the total lockouts.
- **Gates check artifact presence or self-attestation, with enforcement gaps** — Done, proof and review gates accept that a log line, test mapping or stamp exists without checking that it proves the behavior. Many workflow rules are advisory prose: ticket-first, handbook-first, TDD RED-before-green, verify before done, refactor and audit. Ticketless work, task tickets and Bash writes bypass the hooks. Binding gates to verifiable evidence and closing coverage gaps at the transition edits would stop false 'done' claims.
- **Safeword mutates the user's working tree and git state as an unscoped side effect** — Auto-upgrade and install commit or stash on the active branch without consent. They rewrite every managed file instead of the requested scope, write before validating, ignore --offline and --no-modify, and lump unrelated health findings into their exit status. Runtime state files and regenerated docs land in tracked, un-gitignored paths. Scoping writes to the requested artifacts, making installs atomic and consent-gated, and keeping runtime state outside or gitignored would stop dirty trees and churn on feature branches.
- **Review packets misscoped and review loops lack scope bounds or convergence** — Reviews take whole files rather than diffs and are confined to the project root. They have fixed byte and file caps with no handling for generated files, are missing context the rubric needs (ticket.md, parent epic, personas), and use a rubric copied separately from the authoring guidance. Stateless reviewers then surface new marginal findings every round with no stopping rule, and consent and egress disclosure is requested late and vaguely. Diff-scoped packets with automatic context assembly, a shared rubric, convergence criteria and upfront named-destination consent would let gates terminate.
- **Tests are non-hermetic or assert on prose and proxies** — Safeword's own tests rely on chmod under root, ambient PATH, HOME and session env, the real global Claude plugin store, full git tag history and tight wall-clock bounds. Many assert on template wording or mocked paths rather than behavior, so they flake under load or pass vacuously. Isolating the environment by default, guarding for root, shallow clones and load, and asserting real boundaries would make the suite trustworthy.
- **Dependency-readiness gate uses mtime/whole-file fingerprints and non-self-healing remediation** — The tool-list/deps-fingerprint gate infers staleness from node_modules mtimes or a hash of the whole package.json. It runs on every Bash call, before chained commands execute, and its prescribed fix (touch, rm -f, bun ci) is cwd-relative, forbidden by host policy or invalid for bun. Comparing only dependency fields against actual install state, refreshing the fingerprint automatically after install, and scoping the gate to dependency-using commands would remove most false blocks and manual recovery rituals.
- **Review stamp writer, receipt verifier and phase gate disagree on contracts** — The stamp helper finds the verifying CLI only through CLAUDE_PLUGIN_ROOT or the pinned project version. It accepts only bare ticket names, parses --help as an artifact, requires ticket-local targets and an exact coverage set that isn't shown in advance, and writes stamps the gate can't find. Sharing one contract and CLI resolver across the runner, stamp writer and gate, and verifying receipts by review id, would end both the lost approvals and the forgeable self-attested stamps.
- **Verification, lint and audit scope not mapped to the changed module or diff** — test-plan, the lint hooks, verify and audit assume repo-root context and run whole-repo suites. They skip nested Go modules and workspace packages, run golangci from the root, lint single files in isolation, and duplicate overlapping lanes. Mapping changed files to their owning package or module, deduplicating lanes and scoping findings to the diff would turn verification into ticket-specific signal instead of environment noise.
- **Machine-wide Vitest build lock shared across all worktrees with short timeout** — A single global build lock serializes every test run on the machine across all checkouts. It has a 60s default wait, no queue or fairness, and no visibility into who holds it, and a timeout exits like a real test failure. Scoping the lock to the contended dist artifact or worktree, queueing with progress output, and giving contention its own exit status would end the starvation and misreported verification failures.
- **Stop-hook reply-format contract applied context-blind with drifted specs** — The Stop hook treats every turn end as a terminal implementation handoff. It enforces a strict decision-brief or verdict grammar regardless of turn type, ticket presence, background waits or unattended runs, and the SessionStart bootstrap and the validator define different grammars. One shared canonical contract, with turn-type detection and targeted error messages, would stop the repeated rewrite round-trips and the contradictory corrections.
- **Independent reviewer routing fails and silently degrades to self-review** — The review coordinator invokes external reviewer CLIs with inconsistent flags such as --json-schema and --output-schema. It misclassifies auth, sandbox and trust failures, and uses hardcoded timeout ceilings and shared deadlines, so it exhausts its routes and falls back to a same-agent review that either can't read targets or can't satisfy the gate. Consistent route invocation, accurate error classification, preflight of reviewer availability, and an honest, loud degraded path would make review dependable.
- **Guards judge edits by brittle syntactic heuristics instead of resulting state** — PreToolUse guards try to reconstruct canonical ticket edits, grep shell text for protected paths, parse ledger lines, and validate prerequisites against pre-edit disk state. They fail closed when the heuristic can't handle a valid shape. Validating the post-edit content, or the actual write targets, with tolerant parsers would unblock legitimate multi-hunk patches, read-only commands and atomic multi-file edits.
- **Host agent and environment behaviors Safeword assumes away** — Some friction comes from the host or toolchain rather than Safeword logic. Examples include Claude Code resetting cwd, the auto-mode classifier protecting .claude/skills, plan filenames slugged from injected reminders, bunx writing to stdout and racing on temp dirs, sandbox tempdir limits and the fixed 120s Bash timeout. Detecting these conditions and documenting or working around them, for instance with pipefail, a REST fallback or explicit paths, would reduce misattributed failures.
- **Project root resolved from cwd or launch checkout instead of the owning worktree or repo** — Hooks, CLI commands and state writers resolve the project root in inconsistent ways. Some use the literal process cwd, some use CLAUDE_PROJECT_DIR or the session's launch checkout, and some walk up to the nearest .git, so nested repos, subdirectories and sibling worktrees get the wrong tickets, state and lint scope. A single resolver that anchors to the enclosing Safeword install of the edited file or command workdir would fix the misclassified edits, the stray .safeword trees and the guards that evaluate the wrong checkout.
- **Bootstrap and skill guidance is oversized, path-ambiguous and model-triggered** — Session bootstrap tells agents to read a 'packaged handbook' and guides without a concrete path, even though the files may not be installed. That material, and some skills, exceed host read limits or embed large scripts inline. Skill routing (debug, bdd, elicit, retro) depends on the model noticing description triggers. Smaller, path-explicit, phase-relevant guidance with deterministic routing would reduce discovery toil and skipped workflows.
- **Retro filing pipeline publishes publicly with weak consent, sanitization, dedup and drain** — Retro auto-files agent-authored findings to a public tracker under the user's identity without confirmation. It sanitizes only structural patterns and derives dedup signatures from unstable fields, and its spool/filer handoff lacks atomic ack, session scoping and loop-until-drained behavior. A consented, deduplicated, semantically sanitized pipeline with one shared filing path and durable acks would stop duplicate floods, leaks and repeated nudges.
- **Worktree provisioning omits dependencies, trust, context and cwd handling** — Worktree creation produces a bare checkout. It doesn't install or link node_modules, run mise trust, carry .project and enrollment state, set hook executable bits, or pin the shell cwd, and recycling moves paths mid-session. Provisioning that bootstraps dependencies, toolchain trust and ticket context, and tracks cwd, would make hooks and pre-commit tooling work in fresh worktrees.
- **Ticket CLI lacks lifecycle and structured-edit verbs, forcing hand edits of guarded files** — The ticket CLI only creates and lists. It has no commands to transition phase or status, close, link a parent, set fields, look up an ID, or report state, and its output omits the new ID and path. The status and type models are also incomplete. Agents therefore hand-edit frontmatter that hooks police, and index sync drifts. First-class mutation and query commands over a validated schema would remove this toil and the guard collisions.
- **Closeout evidence checks fail open and mishandle receipts** — Closeout cleanup treats failed git reads as a clean tree and an empty verification plan as passing. It reuses preview-time state (a TOCTOU gap), keys retro receipts on a shared git dir or a growing live transcript, and rejects hosted-CI evidence. Its handling of retrospective capture is also inconsistent. Failing closed on unobserved state, binding receipts per worktree and stable snapshot, and one shared retro policy would make closeout trustworthy and non-repetitive.
- **LOC-since-commit gate counts raw uncommitted lines without context** — The pre-tool LOC gate counts every uncommitted line in the working tree with a fixed threshold, and it fires on each Edit rather than at logical boundaries. That count includes generated or regenerated output, Safeword's own install churn, deletions, other sessions' dirt and out-of-repo writes. Attributing only hand-authored, session-owned changes and accounting for phase or green state would stop forced mid-change WIP commits.
- **Review and RED receipts invalidated by their own bookkeeping edits** — Review stamps, RED approvals and receipts hash whole files (ticket.md, the test-definitions ledger, implementation context) or exact HEAD SHAs. Edits the gate itself requires, such as phase_anchors, ledger ticks, work-log lines, or committing verify.md, then invalidate valid approvals. Binding fingerprints only to the reviewed semantic content, excluding mutable workflow metadata, would stop the forced re-reviews and circular sequencing.
