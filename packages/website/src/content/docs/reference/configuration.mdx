Most projects work great with the defaults. This page covers customization when you need it.

## ESLint Setup

Safeword includes an ESLint plugin with sensible defaults. Your `eslint.config.mjs`:

```js
import { defineConfig } from 'eslint/config';
import safeword from 'safeword/eslint';

export default defineConfig([
  ...safeword.configs.recommendedTypeScript,
  ...safeword.configs.vitest, // if using Vitest
]);
```

Safeword's generated config uses [`defineConfig`](https://eslint.org/docs/latest/use/configure/configuration-files#the-defineconfig-helper) (ESLint ≥10.4) — the canonical flat-config helper. It enables file-scoped `extends:` and validates the config shape at lint time.

**Available configs:**

| Config                       | Use case                                                                                             |
| ---------------------------- | ---------------------------------------------------------------------------------------------------- |
| `recommended`                | JavaScript only                                                                                      |
| `recommendedTypeScript`      | TypeScript                                                                                           |
| `recommendedTypeScriptReact` | TypeScript + React                                                                                   |
| `recommendedTypeScriptNext`  | TypeScript + Next.js                                                                                 |
| `nextOnlyRules`              | Next.js rules for monorepo file scoping                                                              |
| `vitest`                     | Add Vitest support                                                                                   |
| `playwright`                 | Add Playwright support                                                                               |
| `astro`                      | Add Astro support                                                                                    |
| `tailwind`                   | Add Tailwind support                                                                                 |
| `tanstackQuery`              | Add TanStack Query                                                                                   |
| `storybook`                  | Add Storybook support                                                                                |
| `turbo`                      | Add Turborepo support                                                                                |
| `cli`                        | CLI tools, build tools, scripts — disables security rules that flag dynamic paths and shell commands |
| `relaxedTypes`               | JSON/YAML parsing, API clients, config files — disables strict TypeScript rules for untyped data     |

Apply the `cli` and `relaxedTypes` presets globally by adding them to the array:

```js
export default defineConfig([
  ...safeword.configs.recommendedTypeScript,
  safeword.configs.cli, // if building a CLI tool
  safeword.configs.relaxedTypes, // if handling untyped external data
]);
```

Or scope them to a subset of files using `extends:` — useful when only scripts or config loaders need the relaxations:

```js
export default defineConfig([
  ...safeword.configs.recommendedTypeScript,
  {
    files: ['scripts/**', 'config/**'],
    extends: [safeword.configs.cli, safeword.configs.relaxedTypes],
  },
]);
```

To add your own rules or override individual rules directly, add another entry to the array:

```js
export default defineConfig([
  ...safeword.configs.recommendedTypeScript,
  {
    rules: {
      'no-console': 'warn',
      'security/detect-non-literal-fs-filename': 'off', // override a single rule
    },
  },
]);
```

## Language Detection

Safeword auto-detects your stack and configures linting accordingly:

| Language       | Linting           | Type Checking | Architecture       |
| -------------- | ----------------- | ------------- | ------------------ |
| TypeScript     | ESLint + Prettier | tsc           | dependency-cruiser |
| Python (beta)  | Ruff              | mypy          | import-linter      |
| Go (beta)      | golangci-lint     | go vet        | —                  |
| Rust (beta)    | clippy            | rustc         | —                  |
| SQL/dbt (beta) | SQLFluff          | —             | —                  |

Detection is stored in `.safeword/config.json`. To force a refresh, delete that file and run `safeword install` again.

Edit-time linting uses the generated language-pack config when it exists. For JavaScript/TypeScript, Python, Go, and Rust, a missing config falls back to the tool's defaults and reports once per session that Safeword rules are not active. SQLFluff runs only when its generated config exists. The lint hook never repairs a pack, runs installation, stages files, or creates a commit. Version convergence remains the responsibility of the session-start updater; to repair a missing pack manually, run `safeword install`.

## Biome & Alternative Formatters

If your project uses Biome, dprint, or Rome, Safeword detects it automatically and skips Prettier installation. Your formatter keeps running as-is.

**Safeword still installs ESLint.** This is intentional — Biome doesn't support:

- **Security scanning** — catches unsafe patterns like `eval()`, non-literal regex, prototype pollution
- **Cyclomatic complexity** — flags overly complex functions that AI agents tend to generate
- **Framework-specific rules** — React hooks, Next.js best practices, Astro components

Both tools coexist cleanly — ESLint handles code analysis (bugs, security, complexity) while Biome handles formatting. Safeword configures Biome to ignore safeword's own files.

| With Biome        | Without Biome     |
| ----------------- | ----------------- |
| ESLint (devDep)   | ESLint (devDep)   |
| safeword (devDep) | safeword (devDep) |
| jiti (devDep)     | jiti (devDep)     |
| _(no Prettier)_   | Prettier (devDep) |

## SQL Formatting

Your project's chosen SQL formatter owns SQL formatting; safeword adapts to it:

- **If your project formats SQL with Prettier** (`prettier-plugin-sql` in your dependencies), safeword defers entirely: install skips the SQLFluff configs (`.sqlfluff`, `.safeword/sqlfluff.cfg`), and the edit-time hook runs _your_ Prettier with _your_ config — so `.prettierignore` carve-outs (like frozen DDL migrations) are honored. Adopting `prettier-plugin-sql` in a repo that already has safeword-generated SQLFluff configs? Delete `.sqlfluff` and `.safeword/sqlfluff.cfg`; upgrades won't recreate them.
- **Otherwise**, safeword lints SQL with SQLFluff: the edit-time hook runs `sqlfluff lint` and reports violations to the agent. In-place rewriting is opt-in — set `"sql": { "fix": true }` in `.safeword/config.json` to have the hook run `sqlfluff fix` on edited files. SQLFluff honors `.sqlfluffignore`, so you can exclude files (e.g. applied migrations) from rewriting.

## Hook Configuration

Claude Code hooks run from the Safeword plugin installed with `safeword install --agents=claude`. Project scope is the default and records activation in `.claude/settings.json`; `safeword install --agents=claude --scope user` activates it across projects. Cursor hooks are configured in `.cursor/hooks.json`; Codex uses its profile-scoped plugin. Fresh install does not create legacy Safeword-owned Claude hook settings. On an upgraded project, the first successful prompt handled by the exact current plugin automatically removes only byte-for-byte recognized Safeword legacy files and hook entries. Modified, malformed, or third-party content is preserved and reported without blocking the prompt. See [Hooks & Skills](/reference/hooks-and-skills) for what runs automatically.

To disable a specific hook, remove the safeword hook entry from that agent's config.

### Review gates

Work moves through phases — `intake`, `define-behavior`, `scenario-gate`, `plan-implementation`, `implement`, `verify`, `done` — and a phase change is an edit to `phase:` in the ticket's `ticket.md`. The phase-exit review gate reads that edit before it lands and blocks it until the phase you are leaving carries an independent review stamp (a fresh-context reviewer, logged via `write-review-stamp.ts --phase <phase>`), or an explicitly logged skip reason.

**This gate is on at every exit by default**, including on a fresh install with no `reviewGate` key. Choose which exits it guards:

| `reviewGate` value                     | Effect                                                               |
| -------------------------------------- | -------------------------------------------------------------------- |
| _(key absent)_                         | Every phase exit needs a review stamp. The default.                  |
| `true`                                 | Same, and additionally turns on the per-asset inline stamp (Tier 1). |
| `["define-behavior", "scenario-gate"]` | Only the exits you name. Everything else advances silently.          |
| `false`                                | Off entirely.                                                        |

A list is the usual way to tune this: it buys independent review where judgment carries the phase and skips exits that machine evidence already guards — `implement → verify` has tests, `verify → done` has the done gate. An unusable value (a bare string, a number, malformed JSON) keeps the default rather than reading as off, so a typo can't quietly remove a gate; an empty list is a considered choice and does disable it.

Each blocked exit tells you the phase, the command to run, and how to narrow the gate. One review takes roughly half a minute on the default route.

- `architectureReviewGate: true` — opt-in, default off. A new-flow feature can't reach verify/done until its `impl-plan.md` design has been independently reviewed: the Decisions section must cite evidence (URL or `[n]` marker), and the review stamp binds to the plan's content hash — editing the design after review invalidates it. Add `crossModelReview: true` to require the reviewer run on a different model than the author.
- `stopQualityReview: true` — opt-in, default off. Restores the review prompt and the decision-brief reply contract that used to fire when the agent finished a turn. It was measured at one intervention (a reply reformat) across ~220 turn-ends and never a code change, because the moment an agent stops has no relationship to the work; the phase-exit gate above asks at the moment the work actually moves. The Stop hook's evidence gates — done, impl-plan, architecture, cumulative artifacts, typecheck advisory — are unaffected and always run.

Adversarial reviews use `crossAgentReview` to choose their reviewer route:

```json
{
  "crossAgentReview": "prefer",
  "crossAgentReviewPrimaryModel": {
    "claude": "opus"
  },
  "crossAgentReviewAlternateModel": {
    "claude": "sonnet",
    "codex": "gpt-5-codex"
  }
}
```

Power users can replace the legacy fixed fallback chain with an exact per-author order:

```json
{
  "crossAgentReview": "prefer",
  "crossAgentReviewRoutes": {
    "claude": [
      { "reviewer": "codex", "model": "gpt-5-codex" },
      { "reviewer": "opencode", "model": "openai/gpt-5" },
      { "reviewer": "claude" }
    ]
  }
}
```

Each route names `claude`, `codex`, or `opencode` and may name one model. Omitting `model` deliberately uses that runtime's authenticated default. When `crossAgentReviewRoutes` is present it is the complete authority: Safeword neither merges legacy primary/alternate settings nor reorders routes from cached health observations. Empty lists, unknown runtimes, and option-shaped or otherwise unsafe model identifiers reject the configuration without launching a reviewer. A same-author route is always reported as degraded, wherever it appears, and Safeword continues looking for a later independent success.

Set personal routes once in the Safeword user profile, or commit a project override:

```sh
safeword review routes set --author claude \
  --route codex=gpt-5-codex \
  --route opencode=openai/gpt-5 \
  --route claude
safeword review routes set --scope project --author codex --route claude=opus
safeword review routes list --author claude
safeword review routes reset --author claude
```

The default scope for `set` and `reset` is `user`; pass `--scope project` explicitly for repository configuration. Each repeated `--route` is one fallback in order and uses `reviewer=model`; omit `=model` to use that reviewer's authenticated runtime default. `--author` selects whose authored work the chain applies to.

On macOS and Linux the user profile is `$XDG_CONFIG_HOME/safeword/config.json`, falling back to `~/.config/safeword/config.json`. On Windows it uses `%XDG_CONFIG_HOME%\safeword\config.json` when set, then `%APPDATA%\Safeword\config.json`, then `%USERPROFILE%\.config\safeword\config.json`. For each author independently, a project entry replaces the user entry, which replaces the built-in chain; lists are never merged. Because project configuration is repository-controlled, it can replace a user's independent chain with degraded same-author routes, just as the existing project-level `crossAgentReview` setting can select `prefer` or `off`; review repository configuration before trusting its coverage policy. Reset removes only that author at the selected scope, preserving other Safeword settings and revealing the next scope.

Only `crossAgentReviewRoutes` is user-scoped today; review policy and legacy primary/alternate model settings remain project-scoped. Effective route reads validate both files before applying precedence, so malformed JSON in either file fails visibly even when the other scope has a route. Fix or remove the named malformed file, then retry.

- `prefer` (default) — Claude-authored work is sent to headless Codex and Codex-authored work to headless Claude. If the preferred reviewer and its eligible alternate-model route cannot complete, Safeword tries OpenCode once before running a same-agent headless fallback. OpenCode-authored work routes to Claude and then Codex; OpenCode self-review is never independent. A completed same-agent result is presented as standard coverage; requested details can suggest how to add independent coverage. If every CLI route fails, a foreground agent may add supplemental host-native or self-review findings; their actual verdict is preserved.
- `require` — only an opposite-agent result satisfies the gate. A completed same-agent headless review returns the existing independence-required failure. If every CLI route fails, a foreground agent may still report useful host-native or self-review findings, but the result remains action required, recommends restoring an independent reviewer or explicitly choosing `prefer`, and never writes independent evidence.
- `off` — retain the existing review route and do not create cross-agent evidence.

Authentication is recoverable reviewer state, not a failed route. If a preferred or alternate independent route is not signed in, Safeword returns `REVIEW_AUTHENTICATION_REQUIRED` with that reviewer's login command and does not start a same-agent fallback. Managed agent workflows run the command, allow any browser or device login to finish, and retry the same review once; another authentication denial remains an explicit blocker.

Without `crossAgentReviewRoutes`, Safeword retains the legacy chain and selects Claude's `opus` alias for the primary independent review and `sonnet` for its alternate attempt. Codex continues to use its authenticated profile unless configured. Override either legacy route per agent with `crossAgentReviewPrimaryModel` or `crossAgentReviewAlternateModel`; environment variables `SAFEWORD_REVIEW_PRIMARY_MODEL_CLAUDE`, `SAFEWORD_REVIEW_PRIMARY_MODEL_CODEX`, `SAFEWORD_REVIEW_ALTERNATE_MODEL_CLAUDE`, and `SAFEWORD_REVIEW_ALTERNATE_MODEL_CODEX` take precedence. Model identifiers must be 1–200 characters using letters, digits, `.`, `_`, `:`, `/`, or `-`, and cannot begin with `-`.

For projects that opt into ranked routes, `safeword status` reports each configured route in order for the detected Claude, Codex, or OpenCode author runtime. A plain terminal with no detected author does not select an author-specific route list. Installation and compatibility come from bounded local inspection; OpenCode model routes also report whether the exact provider-qualified model appears in `opencode models --pure`. Catalogue presence is not proof that credentials or inference work. Only the most recent integrity-validated review job for the exact runtime plus explicit model—or the explicit runtime-default marker—reports `proven` or `known_failure`. Older records without that exact identity prove nothing. `--offline` skips this optional catalogue inspection while preserving the remaining local status checks.

Foreground review attempts default to two minutes, with packet preparation and reviewer work across all routes bounded to four and a half minutes. Durable background review attempts default to ten minutes within a thirty-minute shared bound. Final synchronous integrity checks and bounded process cleanup may finish after the shared deadline. `SAFEWORD_REVIEW_TIMEOUT_MS` and `SAFEWORD_REVIEW_RUN_BOUND_MS` accept positive millisecond values when a caller needs shorter limits; neither can raise the applicable foreground or background ceiling.

Keep each review packet to the smallest coherent set of artifacts that lets the reviewer judge the change: include the implementation together with directly coupled tests, contracts, and documentation, but split unrelated subsystems into separate reviews. This preserves enough context for a meaningful verdict without making the primary route consume the alternate route's reserved time.

Desktop and managed cloud sessions reuse each CLI's existing authentication; Safeword does not copy API keys between vendors or expose credential values. OpenCode is a multi-provider runtime, so selecting it as a route makes the provider credentials already present in the caller's environment available to that OpenCode reviewer process. Install and sign in to at least one independent headless CLI for independent coverage. A model-specific route requires the runtime to advertise model selection. Human output calls a validated same-agent result standard coverage and a validated different-agent result independent coverage; machine results retain exact ordered-route evidence and `cross-agent`, `degraded`, or `none` independence so stamps and automation can enforce the configured policy.

### Advisory pull request review

The GitHub Actions advisory reviewer is default off. Enable it with a complete
`prReview` block, then run `safeword install` to generate the router and reusable
worker workflows:

```json
{
  "prReview": {
    "enabled": true,
    "provider": "openai",
    "model": "gpt-5.2",
    "maxTotalBytes": 100000,
    "requiredChecks": [{ "context": "ci" }]
  }
}
```

| Key              | Meaning                                                                                                                                         |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`        | Must be `true` before install generates the workflows.                                                                                          |
| `provider`       | Currently `openai`.                                                                                                                             |
| `model`          | Non-empty OpenAI Responses model name.                                                                                                          |
| `maxTotalBytes`  | Positive integer cap applied cumulatively in GitHub's file order. Text beyond the cap is reported as missing evidence and forces `needs_human`. |
| `requiredChecks` | Exact check-run names or commit-status contexts. `[]` means no prerequisites; omission is an unconfigured, route-free result.                   |

Create a GitHub environment named `safeword-pr-review-model` and store
`OPENAI_API_KEY` there. Do not add deployment protection rules, a wait timer, or
required reviewers: those controls would prevent the non-deployment inspection
job from reading the secret. The inspection job is read-only and never checks
out pull-request code; the separate publication jobs can only reconcile the
ordinary issue comment and never receive the model secret.

Each pull-request event samples prerequisites once. Pending or absent configured
checks produce a visible non-run receipt and are reconsidered by the scheduled
five-minute sweep; terminal prerequisite failure remains route-free. Every new
head SHA is reviewed from scratch. Draft, closed, or merged state removes an
existing route without creating a new receipt. A provider failure is terminal
for that SHA and routes to a human; push a new SHA to request a fresh review.

The workflow classifies recognized binary filename extensions as skipped. A
missing GitHub patch for any other path is treated as unreadable text and fails
closed. Runtime environment-secret scoping and event/sweep serialization remain
a required disposable-repository release smoke before enabling this feature.

### Design approval gate

`designApprovalGate` (default: off) keeps the plan-implementation phase autonomous: the independently reviewed implementation plan advances to TDD without a human checkpoint. Technical builders who want to approve the design before any code can opt in:

```json
{
  "designApprovalGate": true
}
```

When enabled, the agent presents the reviewed plan (riskiest assumption, build order, decisions) and waits for approval before entering the implement phase. In headless/cloud sessions the pending approval is recorded in the ticket work log and the plan surfaces in the session's reviewable output instead of stalling the run.

## Customizing Without Losing Upgrades

Safeword has two types of files:

**Overwritten on upgrade** (you shouldn't edit these directly):

- `.safeword/hooks/*`, `.safeword/guides/*`, `.safeword/templates/*`
- `.cursor/rules/*`, `.cursor/commands/*`

**Never overwritten** (safe to customize):

- `eslint.config.mjs`, `.prettierrc`, `tsconfig.json`, `knip.json`, `cucumber.mjs`
- Language-specific configs: `ruff.toml`, `mypy.ini`, `.golangci.yml`, `clippy.toml`, `rustfmt.toml`, `.sqlfluff`

**Created once, yours afterward** (scaffolded if missing, never overwritten once you've edited them):

- `features/` — Gherkin `.feature` files (a runnable starter is scaffolded)
- `steps/` — TypeScript step definitions for the acceptance lane

**Partially updated** (your customizations preserved, safeword keys re-merged):

- `AGENTS.md`, `CLAUDE.md` — safeword link block re-ensured, your content preserved
- `.cursor/hooks.json` — safeword hooks updated, your custom hooks preserved
- `package.json` — lint/format/`test:bdd` scripts and devDependencies merged (every project; created minimal + private if missing)
- `.mcp.json`, `.cursor/mcp.json` — MCP server config merged
- `biome.json` — safeword ignore patterns merged (if Biome detected)

**To customize something that gets overwritten:**

1. Copy it to your namespace root (e.g., `.project/my-hook.ts` — see [Project Namespace Root](#project-namespace-root))
2. Point the project-local surface that owns the customization at your copy
3. Your version won't be touched by upgrades

## Project Namespace Root

Safeword's project knowledge — tickets, learnings, principles, personas, glossary, surfaces, architecture record — lives under a single **namespace root** directory, resolved in this order:

1. `paths.projectRoot` in `.safeword/config.json`, if set
2. `.project/` — the default for new installs
3. `.safeword-project/` — the legacy root, honored where it already exists

A project with neither directory resolves to `.project/`.

The `paths` object also supports per-file overrides — `principles`, `personas`, `glossary`, `surfaces`, and `architecture` — which default to matching `.md` files under the resolved root. A per-file key wins over the root for its file.

Persona headers may carry an explicit short code, for example `## Platform Operator (PO)`. Automatic codes use **3–4 letters** (`Platform Operator` → `PLO`); explicit overrides may use **2–4 letters**. Carry the resolved code unchanged through JTBD ids and Gherkin lineage (`oauth-flow.PO1.R1`). Safeword still accepts existing explicit 5–6 character codes and resolves former derived aliases, so upgrading does not require renaming historical specs or scenarios.

Two directory keys, `features` and `steps`, point the BDD acceptance lane at relocated (or host-owned) directories. Unlike the per-file overrides they **augment** the defaults rather than replace them: `safeword project codify`, `safeword project lint-gherkin`, and the `safeword doctor` spec gate read the configured `features` directory _in addition to_ root `features/` and the workspace-package conventions, and the scaffolded `cucumber.mjs` runner reads both keys (`steps` matters only to the runner, for relocated TypeScript step definitions). Set them when your acceptance suite lives elsewhere (e.g. `tests/behaviors` + `tests/steps`), including when install detected an existing cucumber harness and skipped the starter lane:

```json
{
  "installedPacks": ["typescript"],
  "paths": {
    "projectRoot": ".project",
    "principles": "docs/principles.md",
    "personas": "docs/personas.md",
    "glossary": "docs/glossary.md",
    "surfaces": "docs/surfaces.md",
    "architecture": "docs/adr/",
    "features": "tests/behaviors",
    "steps": "tests/steps"
  },
  "docs": {
    "sources": [
      { "type": "local", "path": "README.md" },
      { "type": "local", "path": "docs" },
      { "type": "url", "url": "https://docs.example.com" },
      { "type": "git", "repo": "git@example.com:org/docs.git", "path": "product" }
    ]
  }
}
```

Relative paths resolve against the project root (the directory containing `.safeword/`); absolute paths are used verbatim.

`principles.md`, `personas.md`, and `surfaces.md` share one safe ownership
lifecycle. Install scaffolds a missing default, preserves authored content
byte-for-byte, and suppresses the default scaffold when the matching
`paths.principles`, `paths.personas`, or `paths.surfaces` override is present.
Doctor fails non-zero with a key-specific error when a configured file is
missing. When an override and its default both exist, doctor reports a zero-exit
orphan advisory naming both paths; Safeword never deletes user-authored
knowledge, so cleanup remains an explicit user choice.

For adopted host harnesses with a house style, `bdd.conventions` points at a conventions document the host owns — what an unimplemented step body looks like, how spec-ahead scenarios are verified without executing them (for example a cucumber dry-run/check profile), and which tags the host's profiles exclude by default:

```json
{
  "bdd": {
    "conventions": "tests/CONVENTIONS.md"
  }
}
```

When set, `safeword project codify` prints a pointer to the doc alongside its output, and the installed BDD skill prose directs agents to read and follow it over safeword's defaults. Safeword never parses or validates the doc — it lives next to the harness and is maintained by whoever maintains the harness, so it cannot drift the way conventions transcribed into skill prose do.

`surfaces.md` is optional project knowledge for BDD. Use it for recurring product, agent, runtime, protocol, client, or deployment contexts where behavior must keep working, such as Claude Code, OpenAI Codex, Cursor, web, mobile, MCP, cloud service, or self-hosted deployments. Keep one-off contexts in a feature spec's `## Surfaces` section unless they recur across tickets, are ambiguous enough to drift, or are important enough that missing them would leave a context untested. When a spec lists affected surfaces, saved `.feature` scenarios should cover them with `@surface.<slug>` tags or explicit `skip:` reasons.

`docs.sources` is separate from `paths.*`. Use it to tell audit where project documentation lives. Local sources are validated by `safeword doctor`; URL and git sources are treated as audit inventory and should be fetched during audit when access is available, or reported as skipped coverage when they are not accessible. Set `"docs": { "sources": [] }` to keep fallback discovery and stop future audits from asking for configured sources.

## Project-Specific Content

Put custom content in your namespace root (`.project/` by default):

- Custom hooks
- Project-specific guides
- Team conventions

This folder is yours—Safeword will never modify it.

## Tracker Integration (`ticketBridge`)

Mirror local tickets one-way into GitHub Issues or Linear. Off by default; configured via
`safeword tracker connect`. See [Tracker Integration](/reference/tracker-integration/) for the full guide.

```json
{
  "ticketBridge": {
    "provider": "none",
    "body": "minimal",
    "target": { "repo": "owner/name" }
  }
}
```

| Key        | Values                       | Meaning                                                                                                                                    |
| ---------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `provider` | `none` · `github` · `linear` | Which tracker to mirror to. `none` (default) is inert.                                                                                     |
| `body`     | `minimal` · `full`           | Issue body egress. `minimal` (default) = title/status/labels/back-link only; `full` opts in to the ticket body and warns on a public repo. |
| `target`   | `{ repo }` / `{ team }`      | GitHub repo (`owner/name`) or Linear team.                                                                                                 |

Credentials resolve from the OS keychain or an environment variable only — never from this file.
