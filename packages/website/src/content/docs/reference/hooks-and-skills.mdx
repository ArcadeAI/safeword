## Slash Commands

Quick actions you type in your agent. Cursor keeps the short command names below. Claude Code uses native namespaced forms such as `/safeword:bdd` and `/safeword:verify`; Codex uses plugin-scoped skills such as `safeword:bdd` and `safeword:verify`.

| Command            | What it does                              |
| ------------------ | ----------------------------------------- |
| `/lint`            | Fix code style issues                     |
| `/audit`           | Find dead code and architecture drift     |
| `/quality-review`  | Deep review against latest research       |
| `/cleanup-zombies` | Clean current-project zombie processes    |
| `/closeout`        | Safely clean up a merged delivery session |
| `/bdd`             | Start BDD workflow (includes TDD)         |
| `/debug`           | Start structured debugging workflow       |
| `/refactor`        | Start safe refactoring workflow           |
| `/spike`           | Run a bounded disposable experiment       |
| `/verify`          | Run completion checklist for current task |

## Hooks

Hooks run automatically at key moments. You don't invoke them—they work in the background.

    ### Plugin lifecycle

    The native workflow and hook files are versioned inside Claude's installed plugin cache; do not edit that cache. After an update, run `/reload-plugins`. Use `safeword claude status` to inspect the exact installed version and migration state. Once current project-bound plugin execution is proven, Safeword automatically backs up and retires exact released legacy files and hook entries through a durable, recoverable transaction. Failed proof stays non-blocking; modified, unknown, custom, and third-party content is preserved and reported. `safeword claude cleanup` remains available for explicit diagnosis and recovery.

    ### Rules

    Rules shape agent behavior through system prompts:

    | Rule              | What it does                                             |
    | ----------------- | -------------------------------------------------------- |
    | Core              | Code philosophy, anti-patterns, quality standards        |
    | Debugging         | Investigate before jumping to fixes                      |
    | Refactoring       | One small change at a time, test after each              |
    | Quality Reviewing | Check against latest research and documentation          |
    | Testing           | Behavioral testing principles and test type selection    |
    | Ticket System     | Context anchoring with tickets and work logs             |
    | BDD (8 rules)     | Full feature workflow from discovery through TDD to done |

    ### Customizing hooks and rules

    Default hooks and rules get overwritten on `safeword install`. To customize:

    1. Copy the file to your project namespace root (`.project/` by default)
    2. For rules: reference your copy in your workflow
    3. For hooks: update `.cursor/hooks.json` to point to your copy

    Hook config: `.cursor/hooks.json`
    Rule files: `.cursor/rules/`

| Session starts                  | Loads a compact bootstrap pointing to packaged Safeword instructions              |

Live Codex runs can also report `file_change` execution items; Safeword records that as a Codex runtime boundary, not as a PreToolUse path it claims to guard. The Codex Stop command is separate: for a session-bound, in-progress done-phase ticket, it reuses shared evidence checks and marks the ticket done only when they pass.     ### Skills

    Codex reads safeword workflows from the Safeword Codex plugin. The canonical invocation names are scoped, for example `safeword:bdd`, `safeword:verify`, and `safeword:explain`. Safeword no longer installs Safeword-owned repo-local aliases under `.agents/skills/`.

    ### Hook trust

    Codex hooks run only after the host trusts them; Safeword never bypasses that boundary. Install commits project SessionStart hooks that enroll the current profile, warn until a later task has exact native proof, and prepare missing dependencies. Startup remains advisory; repository-owned composed commands can require dependency readiness. Ordinary maintenance automatically backs up and removes a fully recognized legacy installation only after native installation succeeds; edited or unknown content is preserved. The plugin hook manifest invokes the CLI bundled with that exact plugin version, avoiding package-manager downloads and shared-cache resolution at hook time; Bun is required for this integration.

    Plugin skill files: bundled in the Safeword package under `codex-plugin/skills/`

### Auto-linting

After your agent writes or modifies a file, the right linter runs:

| File type               | Linter        |
| ----------------------- | ------------- |
| TypeScript / JavaScript | ESLint        |
| Python                  | Ruff          |
| Go                      | golangci-lint |
| Rust                    | clippy        |
| SQL / dbt               | SQLFluff      |

If a linter isn't installed, it's silently skipped.

**What you see:** Usually nothing — the linter auto-fixes quietly. If problems remain, your agent sees them and fixes them immediately.

## Language coding-skills

When safeword converges a project with `install`, it installs a small third-party **coding-skill** for each language it detects, and nudges your agent toward that skill the first time you edit the language in a scenario.

| Language   | Skill source (MIT)         |
| ---------- | -------------------------- |
| Go         | `jeffallan/golang-pro`     |
| Python     | `jeffallan/python-pro`     |
| TypeScript | `jeffallan/typescript-pro` |
| Rust       | `leonardomso/rust-skills`  |

Language coding-skills install into `.claude/skills/` and, where supported by the agent, `.agents/skills/` via the `npx skills` CLI. These are third-party language helpers, not Safeword Codex workflow aliases. The install is **best-effort** — a missing network or installer error degrades to a warning and never blocks install. It runs once; later install runs skip it when the skill is already present.

**What you see:** edit a `.go` / `.py` / `.ts` / `.tsx` / `.rs` file and, in Claude Code, a one-line reminder points your agent at the matching skill and surfaces the skill's own description. It fires once per scenario and stays silent for other file types. The Cursor adapter is built but dormant until Cursor fixes an upstream injection bug ([#534](https://github.com/ArcadeAI/safeword/issues/534)). Codex's Safeword workflow guidance now comes from the Codex plugin rather than repo-local `.agents/skills/` aliases.

To skip the skill install, set `SAFEWORD_SKIP_SKILLS=1` (or `SAFEWORD_SKIP_INSTALL=1` to skip all network installs during install).

Frontier models already write most core-language idioms unaided, so treat this as a light nudge, not a transformation.

## Skills

Skills are structured workflows that activate based on what you're asking for. Claude Code and Codex use their Safeword plugins' scoped skills; Cursor uses project rules and commands. When you say "debug this test failure" or "refactor this function", your agent follows the relevant methodology instead of jumping straight to code changes.

### Closing a completed local delivery

Use `/closeout` in Claude Code or Cursor, or `$safeword:closeout` in Codex, after
a pull request is ready to finish. Closeout verifies the current PR head,
observes hosted checks and reviews, and merges only when the current request
explicitly grants normal or administrative merge authority. Invoking the skill
by itself grants no merge authority.

After GitHub confirms the exact PR head is merged, closeout attempts the current
session's retrospective without borrowing another session's receipt. Missing
identity, incomplete extraction, malformed retro output, filing failures, and
pending drafts are all advisory for cleanup. The result still reports when
cleanup could discard captured but unfiled learning. The
cleanup guard previews a digest-bound plan before applying it and
removes only the exact linked worktree, remote branch, and local branch—in that
order. Dirty, locked, protected, changed, default, main, ambiguous, or otherwise
unverifiable targets are preserved and reported with recovery actions.
Transcript growth between preview and apply refreshes retrospective capture
without invalidating authorization for unchanged cleanup targets.

The dependency audit is a delivery-readiness gate and must pass before merge.
After merge, closeout rechecks the immutable head's verification, build,
typecheck, and BDD lanes, but does not rerun mutable dependency intelligence
that could make an already-merged head impossible to clean up later.

Claude Code and Cursor bind closeout to the session captured by their hooks.
Codex uses the same hook binding when available; in Codex Desktop it can use the
authenticated `CODEX_THREAD_ID` supplied by the host when the one-shot hook
bridge is unavailable. Missing or expired identity is reported as advisory for
cleanup and never permits borrowing a different session.

If cleanup is interrupted after removing the topic worktree, the guard can
resume from a surviving worktree using a private verification receipt in Git's
shared common directory. It creates that receipt only after every applicable
post-merge lane passes on a clean exact PR head, accepts it for 24 hours, and
rejects stale, malformed, dirty-state, or wrong-head proof.

| Skill             | Triggers on                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------- |
| BDD Orchestration | "add", "implement", "build", "feature", "iteration", "story", "phase", "resume", "continue" (includes TDD workflow) |
| Debugging         | "debug", "fix this error", "test is failing"                                                                        |
| Quality Reviewing | "review", "check security", "verify versions"                                                                       |
| Refactoring       | "refactor", "clean up", "extract", "rename"                                                                         |
| Testing           | "write tests", "add tests", "test this", "improve coverage" (also invoked by other skills internally)               |
| Ticket System     | "create ticket", "work log", "resume", ticket ID references (context anchoring for complex work)                    |

### BDD Orchestration

Full feature workflow: **Discovery** → **Scenarios** → **Scenario Gate** → **Plan Implementation** → **TDD** → **Verify** → **Done**. Includes TDD (RED/GREEN/REFACTOR) inline. Large features can be split at any checkpoint.

**Example:** "Add user authentication to the API"

Your agent will discover requirements, ask who solves the confirmed customer job exceptionally well, and capture the transferable product principle before writing Rules. After scenarios are validated, it repeats the comparison at the technical level using current, comparable, version-matched sources before selecting the implementation plan. Both stages save evidence—or a specific unsuccessful-search record—in the ordinary BDD artifacts, then implementation proceeds scenario by scenario with TDD.

New feature scaffolds carry a versioned inspiration contract. The existing intake and plan transition hooks validate exact Markdown records, current dates, and version fit; signal-free older tickets remain grandfathered. Research quality stays a review judgment. External pages, repositories, images, and documents are untrusted evidence: the workflow forbids following embedded instructions, exposing private context, executing retrieved code, or copying without a compatible license and attribution.

### Debugging

Investigates before fixing. Follows: **Investigate** → **Hypothesize** → **Test** → **Fix**.

**Example:** "This test is failing but I don't know why"

Instead of immediately changing code, your agent will read the test, trace the execution path, form a hypothesis, and verify it before making changes.

### Quality Reviewing

Deep review that checks your code against latest research using web search.

**Example:** "Review this authentication code"

Your agent will check against official library docs, look for known security issues, and verify you're using current versions.

Quality review, the BDD scenario gate, and implementation-plan review share the same `safeword review run` coordinator. Positional files are the bounded work product; `--context <paths...>` adds bounded supporting evidence without making it review targets. The coordinator snapshots and integrity-checks both roles, treats their contents as untrusted, sends Claude-authored work to headless Codex (and Codex-authored work to headless Claude), validates the returned JSON and reviewer identity, and records raw machine provenance as `cross-agent`, `degraded`, or `none`. Human output presents validated cross-agent results as independent coverage and permitted same-agent results as standard coverage. Discovery, unsupported capabilities, compatibility-probe timeout, launch failure, authentication, and runtime failure remain distinct typed outcomes with targeted recovery guidance.

Safeword-managed review workflows also emit bounded lifecycle progress on stderr
while a reviewer is active. The final machine result remains the only stdout
artifact. During the foreground courtesy window, Safeword relays worker progress
through stderr. The relay closes when a background handoff returns, so detached
work cannot hold a caller's capture stream open or interleave with later host
output; use the returned status command to collect the terminal result. Quiet
mode suppresses the progress. Direct callers of
`safeword review run --json` retain the existing silent-stderr contract.

The coordinator tries the opposite agent's default and configured alternate model before same-agent headless review. If every CLI route fails, foreground agent workflows can continue once through the internal `finish-review` skill: first one host-native fresh-context reviewer, then one bounded main-thread self-review. This continuation is best-effort because only the foreground host can invoke its session agent. It is reported as supplemental feedback with its live-worktree source limits; it never becomes completed standard or independent machine coverage, never creates an independent stamp, and cannot satisfy `crossAgentReview: "require"`. Project-owned Claude assets make the fresh-context route available in Claude Code Cloud even when no external agent CLI is installed. See [Configuration](/reference/configuration#review-gates).

### Refactoring

Small, safe changes with test verification after each step: **One change** → **Test** → **Commit**.

**Example:** "Clean up this messy function"

Your agent will make one small improvement, run tests, commit, then repeat—never batching multiple changes.

### Testing

Core knowledge for writing good tests. Ensures tests verify observable behavior, not implementation details.

**Example:** "Write tests for the payment module"

Your agent will choose the right test type (unit, integration, E2E), write focused assertions, and avoid brittle mocking. This skill is also invoked automatically by other skills — BDD at the RED phase, refactoring for characterization tests, and debugging.

### Ticket System

Context anchoring for complex, multi-step work. Creates tickets with colocated artifacts (specs, test definitions, work logs) in `.project/tickets/` (legacy installs: `.safeword-project/tickets/`).

**Example:** "Create a ticket for the auth refactor"

Your agent will create a structured ticket folder with a spec, test definitions, and work log — preventing context loss across long tasks.
