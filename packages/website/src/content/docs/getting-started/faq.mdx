## What Safeword Is

Safeword is a **process layer** for AI coding agents. It enforces quality practices — BDD/TDD, linting, code review, structured debugging — on top of whatever stack you already use.

**It is not:**

- A framework or library that your application depends on
- An opinion about your tech stack
- A replacement for your existing tools

## Common Questions

### Will Safeword change my stack or application dependencies?

No. Safeword adds development-only code quality tools (`devDependencies`) and configuration files. Your runtime dependencies, application code, and build pipeline are untouched.

For JS/TS projects, it installs ESLint, Prettier, and supporting plugins with the `-D` flag. For Python (beta), Go (beta), Rust (beta), and SQL/dbt (beta), it uses language-native linters (ruff, golangci-lint, clippy, sqlfluff) that are standard development tools.

### Will it overwrite my CLAUDE.md?

No. Safeword neither creates `CLAUDE.md` or `AGENTS.md` nor adds imports to them — a SessionStart hook injects `.safeword/SAFEWORD.md` into each agent session instead. Install only removes an obsolete Safeword link block that an older release prepended, leaving the rest of the file untouched.

### I already use Biome / dprint — is that a problem?

Safeword detects alternative formatters and skips Prettier installation. But it still installs ESLint because Biome and dprint don't cover:

- **Security scanning** — catches unsafe patterns like `eval()`, non-literal regex, prototype pollution
- **Cyclomatic complexity** — flags overly complex functions that AI agents tend to generate
- **Framework-specific rules** — React hooks, Next.js best practices, Astro components

Both tools coexist — ESLint handles code analysis while Biome handles formatting. Safeword configures Biome to ignore safeword's own files. See [Configuration](/reference/configuration) for details.

### Do my teammates need to install Safeword?

No global Safeword install is required. Commit the Safeword project configuration for the surfaces your team uses, including the project-scope Claude declaration and Codex SessionStart hooks. Claude keeps payloads in each user's cache; eligible stable declarations use its native updater, while an explicit update opt-out remains untouched. Codex enrolls each teammate's separate profile and prepares missing dependencies in trusted fresh worktrees. If the plugin cannot protect the current task yet, it warns prominently and gives one next action without blocking work.

### Will it interfere with my development workflow?

No. Safeword's hooks and stricter linting rules only fire during AI agent sessions (Claude Code / Codex / Cursor / OpenCode events). They never run when you code normally. In repos that already use husky, install appends one warn-only line to `pre-commit`/`pre-push` — the boundary evidence check. It reports, never blocks a commit, and `safeword uninstall --agents=none` removes it; safeword never installs a hook manager. Safeword also adds `lint`, `format`, and `test:bdd` scripts to your `package.json` — you can wire these into CI pipelines or precommit hooks if you want, but it's your choice.

### Some lint rules are wrong for my project type

Safeword ships strict rules that are correct for web apps but can be false positives for CLI tools, build scripts, or code that handles untyped data (JSON, YAML, API responses).

Your generated `eslint.config.mjs` already imports `defineConfig` from `eslint/config` — just add an entry to the array.

**Option 1: Use a preset.** Safeword exports named presets that turn off common false-positive groups:

```js
export default defineConfig([
  ...safeword.configs.recommendedTypeScript,
  safeword.configs.cli, // security rules that don't apply to CLI tools
  safeword.configs.relaxedTypes, // strict TS rules that don't apply to untyped data
]);
```

To apply a preset only to a subpath (e.g., scripts folder), use `extends:`:

```js
export default defineConfig([
  ...safeword.configs.recommendedTypeScript,
  {
    files: ['scripts/**'],
    extends: [safeword.configs.cli],
  },
]);
```

**Option 2: Override individual rules.** Add a config object after the base config — later entries win:

```js
export default defineConfig([
  ...safeword.configs.recommendedTypeScript,
  {
    rules: {
      'security/detect-non-literal-fs-filename': 'off',
    },
  },
]);
```

Both approaches work in your project's `eslint.config.mjs`. Safeword's LLM hook honors your project config — customer overrides win on any conflict with safeword's strict rules, so what you disable stays disabled in both your IDE/pre-commit and the LLM hook. The same contract applies to `ruff.toml` (Python) and `.golangci.yml` (Go): edit your project config, your rules win everywhere. See [Configuration](/reference/configuration) for details.

### Can I remove Safeword later?

Yes. Run `bunx safeword uninstall --agents=none --full` to preview the removal, then run the exact `--yes --plan <id>` command Safeword prints. Your application code is unaffected. See [CLI](/reference/cli) for details.

### What if I only want some of the features?

Claude Code uses the project-scoped Safeword plugin by default with `safeword install --agents=claude`; choose `--scope user` to activate it across projects. Cursor hooks remain in `.cursor/hooks.json`; Codex uses its profile-scoped plugin; OpenCode is opt-in with `--agents=opencode`. After the exact current plugin proves it handled a prompt, Safeword automatically retires only recognized legacy Claude entries. Existing custom, modified, malformed, or third-party settings remain yours and are reported without blocking the prompt. See [Configuration](/reference/configuration) for details.
