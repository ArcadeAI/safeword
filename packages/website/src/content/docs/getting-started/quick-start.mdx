One command. Your agent writes better code.

## Install

```bash
bunx safeword@latest setup
```

Takes about 30 seconds. Works with TypeScript, Python (beta), Go (beta), Rust (beta), and SQL/dbt (beta) projects.

Safeword adds code quality tools as devDependencies and configuration files. Your application code, runtime dependencies, and existing configs are unchanged.

## What Changes

You use Claude Code, Cursor, or Codex the same way you always have. Type a prompt, get code. But now there's a safety net running in the background.

<Tabs>
  <TabItem label="Claude Code">
    **Install the native plugin for this project.** Run `safeword claude install`, then `/reload-plugins` inside Claude Code. Project scope is the default and records activation in `.claude/settings.json`; use `safeword claude install --scope user` when you intentionally want Safeword active across every project in your Claude profile.

    **Your agent gets namespaced Safeword workflows.** Native skills use names such as `/safeword:bdd`, `/safeword:verify`, and `/safeword:explain` instead of project-local Safeword skill files.

    **Every edit gets linted automatically.** After your agent writes or modifies a file, Safeword runs your linter. If there are issues, your agent sees them immediately and fixes them—before you even notice.

    **Every session ends with a quality check.** When you're done working, Safeword prompts your agent to review what it built. Catches things like missing error handling, security issues, or code that doesn't match the codebase style.

  </TabItem>
  <TabItem label="Cursor">
    **Your agent follows structured workflows.** Safeword adds rules (`.cursor/rules/`) that guide how your agent approaches tasks. When debugging, it investigates before jumping to fixes. When building features, it follows your codebase patterns.

    **Better decisions, automatically.** The rules kick in based on what you're asking for—no special commands needed.

  </TabItem>
  <TabItem label="Codex">
    **Your agent gets scoped safeword plugin skills.** The Safe Word Codex plugin exposes names such as `safeword:bdd`, `safeword:verify`, and `safeword:explain` instead of installing Safe Word workflow files into your repo.

    **Setup enrolls each repository.** Installing the profile plugin does not enroll every repository you open. Until `safeword setup` creates `.safeword/SAFEWORD.md`, project gates fail open and plugin hooks do not create `.project/` or other project state.

    **PreToolUse gates run through the plugin.** Run `safeword codex install` to refresh, install, and verify the profile-scoped plugin. Restart Codex after installation, start a new task to load one coherent skills-and-hooks catalogue, then review and trust it in Codex. Its hooks use version-pinned Bunx commands. Safeword guards the documented Codex PreToolUse paths it configures: `Bash`, `apply_patch` edit payloads, and file-editing tools.

    **Stop completion and nudges run through Codex continuations.** The packaged `safeword hook codex stop` entrypoint checks shared evidence for the session-bound, in-progress done-phase ticket and marks it done only when that evidence passes. It otherwise continues the turn with exact remediation or advisory text such as an ARCHITECTURE.md drift nudge; it never stages, commits, or opens a PR.

  </TabItem>
</Tabs>

## Try It

Open your project and ask your agent to build something real:

> "Add an API endpoint that returns user profile data"

  <TabItem label="Claude Code">
    Watch what happens:

    1. Run `safeword claude install`, then `/reload-plugins` in Claude Code
    2. Your agent follows namespaced workflows such as `/safeword:bdd`
    3. Lint runs automatically on new code, auto-fixing what it can
    4. If there are issues, your agent fixes them before you even see the code
    5. When you stop the session, a quality review runs automatically

  </TabItem>
  <TabItem label="Cursor">
    Watch what happens:

    1. Your agent investigates your existing API patterns first
    2. It follows the structure of your codebase
    3. If you ask it to debug something, it'll investigate before jumping to fixes

    The rules in `.cursor/rules/` guide this behavior automatically.

  </TabItem>
  <TabItem label="Codex">
    Watch what happens:

    1. Run `safeword codex migrate`, restart Codex, then start a new task
    2. Review the Safe Word plugin in `/hooks`
    3. Your agent follows scoped plugin skills such as `safeword:bdd`
    4. Before supported edits, Codex runs the plugin's version-pinned Bunx PreToolUse hook
    5. Run `safeword codex status`; after current hook proof exists, preview with `safeword codex migrate --finalize` and run its exact `--yes --plan <plan-id>` action
    6. If a safeword gate blocks the edit, your agent gets the denial before changing files
    7. When the agent stops, Codex runs the plugin's Bunx Stop hook to complete verified session-bound done-phase tickets or surface remediation and advisories such as ARCHITECTURE.md drift

## What Got Installed

Safeword added a few folders to your project:

| Folder / surface        | What's in it                                                    |
| ----------------------- | --------------------------------------------------------------- |
| `.safeword/hooks/`      | Project runtime used by supported project-local surfaces        |
| Safe Word Claude plugin | Project-scoped by default; user-scoped when explicitly selected |
| Safe Word Codex plugin  | Profile-scoped Codex workflow skills and hooks                  |
| `.cursor/hooks.json`    | Hook configuration for Cursor                                   |
| `.cursor/rules/`        | Rules for Cursor                                                |
| `.cursor/commands/`     | Slash commands for Cursor                                       |
| `.safeword/`            | Project configuration, guides, and templates                    |

Project-scope Claude activation commits in `.claude/settings.json`; Claude keeps the plugin payload in each user's cache. Each Claude Code user runs `safeword claude install` and `/reload-plugins`. Existing project-local Claude protection remains authoritative until the current plugin records exact execution proof and someone explicitly runs the reviewed `safeword claude cleanup` plan. Each Codex user separately installs and reviews the Codex plugin. Each repository is enrolled with `safeword setup`, which creates the project namespace before plugin hooks write project state.

For JS/TS projects, safeword also adds ESLint and Prettier as **devDependencies** in your `package.json`. These are development-only code quality tools — they don't ship with your application.

Safeword improves over time. Update when you want the latest:

```bash

```

Your customizations are preserved. Only the core files get updated.
