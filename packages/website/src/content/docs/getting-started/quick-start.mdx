One command. Your agent writes better code.

## Install

```bash
bunx safeword@latest install
```

Takes about 30 seconds. Works with TypeScript, Python (beta), Go (beta), Rust (beta), and SQL/dbt (beta) projects.

By default, Safeword configures the project and installs both the Claude Code and Codex profile plugins. Cursor stays untouched unless you explicitly run `safeword install --agents=cursor` (or select all three with `--agents=claude,codex,cursor`). Your application code, runtime dependencies, and existing configs are unchanged.

## What Changes

You use Claude Code, Cursor, or Codex the same way you always have. Type a prompt, get code. But now there's a safety net running in the background.

<Tabs>
  <TabItem label="Claude Code">
    **Install the native plugin for this project.** Run `safeword install --agents=claude`, then `/reload-plugins` inside Claude Code. Project scope is the default and records activation in `.claude/settings.json`; use `safeword install --agents=claude --scope user` when you intentionally want Safeword active across every project in your Claude profile.

    **Hosted sessions (Claude Code on the web) install the same way.** `/plugin` is terminal-only, and declaring the plugin in `.claude/settings.json` does not install it — a hosted session that only has the declaration starts with no Safeword skills or hooks and says nothing about it. `safeword install --agents=claude` is the non-interactive install path: it registers the marketplace, installs the plugin into the host registry, and needs no interactive command. Run it from the session terminal, then resume the session to load the plugin.

    **Your agent gets namespaced Safeword workflows.** Native skills use names such as `/safeword:bdd`, `/safeword:verify`, and `/safeword:explain` instead of project-local Safeword skill files.

    **Every edit gets linted automatically.** After your agent writes or modifies a file, Safeword runs your linter. If there are issues, your agent sees them immediately and fixes them—before you even notice.

    **Every session ends with a quality check.** When you're done working, Safeword prompts your agent to review what it built. Catches things like missing error handling, security issues, or code that doesn't match the codebase style.

  </TabItem>
  <TabItem label="Cursor">
    **Cursor is explicit opt-in.** Run `safeword install --agents=cursor` to install only the project and Cursor integration, or include Cursor in a comma-separated agent selection.

    **Your agent follows structured workflows.** Safeword adds rules (`.cursor/rules/`) that guide how your agent approaches tasks. When debugging, it investigates before jumping to fixes. When building features, it follows your codebase patterns.

    **Better decisions, automatically.** The rules kick in based on what you're asking for—no special commands needed.

  </TabItem>
  <TabItem label="Codex">
    **Your agent gets scoped safeword plugin skills.** The Safeword Codex plugin exposes names such as `safeword:bdd`, `safeword:verify`, and `safeword:explain` instead of installing Safeword workflow files into your repo.

    **Install enrolls each repository.** Installing a profile plugin does not enroll every repository you open. Until `safeword install` creates `.safeword/SAFEWORD.md`, project gates fail open and plugin hooks do not create `.project/` or other project state.

    **Native gates run through the plugin.** Project SessionStart hooks enroll each developer's profile and prepare missing dependencies in trusted fresh worktrees; `safeword install --agents=codex` is available when you want to enroll immediately. Review changed hooks in Desktop Settings > Hooks (or `/hooks` in the terminal TUI), fully restart Codex, then resume this task to load one coherent skills-and-hooks catalogue. Startup warnings remain advisory. Native plugin hooks use the CLI bundled with the installed plugin version, so hook dispatch does not depend on Bunx package resolution.

    **Stop completion and nudges run through Codex continuations.** The packaged `safeword hook codex stop` entrypoint checks shared evidence for the session-bound, in-progress done-phase ticket and marks it done only when that evidence passes. It otherwise continues the turn with exact remediation or advisory text such as an ARCHITECTURE.md drift nudge; it never stages, commits, or opens a PR.

  </TabItem>
</Tabs>

## Try It

Open your project and ask your agent to build something real:

> "Add an API endpoint that returns user profile data"

    2. Your agent follows namespaced workflows such as `/safeword:bdd`
    3. Lint runs automatically on new code, auto-fixing what it can
    4. If there are issues, your agent fixes them before you even see the code
    5. When you stop the session, a quality review runs automatically

    1. Run `safeword install --agents=cursor`
    2. It follows the structure of your codebase
    3. If you ask it to debug something, it'll investigate before jumping to fixes

## What Got Installed

Safeword added a few folders to your project:

| Folder / surface       | What's in it                                                    |
| ---------------------- | --------------------------------------------------------------- |
| `.safeword/hooks/`     | Project runtime used by supported project-local surfaces        |
| Safeword Claude plugin | Project-scoped by default; user-scoped when explicitly selected |
| Safeword Codex plugin  | Project bootstrap plus profile-scoped workflow skills and hooks |
| `.cursor/hooks.json`   | Hook configuration for Cursor                                   |
| `.cursor/rules/`       | Rules for Cursor                                                |
| `.cursor/commands/`    | Slash commands for Cursor                                       |
| `.safeword/`           | Project configuration, guides, and templates                    |

Project-scope Claude activation commits in `.claude/settings.json`; Claude keeps the plugin payload in each user's cache and follows the verified stable channel unless native updates were explicitly disabled. Codex install commits advisory SessionStart hooks for profile enrollment and dependency preparation, and each collaborator's first task enrolls only that collaborator's profile. Until a later task records exact native proof, startup warns that work is unprotected but permits it to continue. Each repository is enrolled with `safeword install`, which creates the project namespace before plugin hooks write project state.

For JS/TS projects, safeword also adds ESLint and Prettier as **devDependencies** in your `package.json`. These are development-only code quality tools — they don't ship with your application.

## Staying Current

Safeword improves over time. Update when you want the latest:

```bash
bunx safeword@latest install
```

Your customizations are preserved. Only the core files get updated.
