# Essential workflow rules are authored once and materialized before host projection

Status: proposed for ticket2ENRH5 implementation review,2026-10-25 UTC.

Startup prohibition superseded only for the bounded existing-handler experiment
by [20261025-startup-essential-delivery](20261025-startup-essential-delivery.md).
The single-owner/generated-body contract otherwise remains in force.

The user selected author-once essential instructions with automatic inclusion in
applicable workflow bodies; optional examples/background remain references.
Generated repetition is permitted. Delivery does not establish comprehension,
guard authority or an unobserved host's behavior.

Reuse the existing typed shared-clause/materialized canonical-template pattern.
One bounded testing-core owner supplies existing wiring/proof-scope clauses to
canonical template consumers and the existing headless quality-review rubric;
schema owns consumer paths. A deterministic generator inserts one current block
before existing native/portable/project projections. Actual generation and
reconciliation entry points reject absent/stale/invalid blocks. No authored
Markdown include language, graph, preloader, reader service or read guard.

Plugin-only expansion was rejected because schema reconciliation copies raw
templates; whole-manual inclusion exceeds the essential-only boundary. A new
managed Markdown core would add source-loading/managed-path machinery without
improving the existing single-owner pattern.

Consequences: generated canonical files repeat bounded text; maintainers edit
only the source owner. Missing producer coverage prevents parity claims. Existing
invocation settings, native guards and all other procedure gates remain intact.
Reverse or extend this choice if the finite consumer set cannot cover an actual
shipping delivery,2048UTF8 bytes cannot hold the existing essential rules, or a
new required behavior cannot be proved without expanding the accepted architecture.
