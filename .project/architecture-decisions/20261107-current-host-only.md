## Status outside the snapshot

An optional unavailable guarantee does not erase independently proved required protection.

Recognized historical Safeword packages that do not declare the contract keep existing activation result/exit semantics with advisory contracted-guarantee-unproved detail; they do not gain a new protection claim. This is old-Safeword-package reconciliation on the current host, not supported older-host conformance. Unknown/stripped markers retain fail-closed integrity rules. Public-status tests distinguish these cases and matching current proof/activation; no native run is inferred from status.

## Alternatives and consequences

Family support would reduce update interruptions but resurrects user-retired version research and infers protection. Advisory-only for new contracted packages is simpler but falsely advertises required enforcement. Blanket failure for historical noncontract packages changes existing semantics without a new claim. Choose explicit unproved current-contract protection plus preserved historical activation semantics because evidence authority controls the claim. No new writer/store/key is needed. Premortem: a host auto-update makes protection unavailable; expose one update-Safeword/restart recovery, preserve config and require fresh release proof rather than silently recycling an older receipt.
