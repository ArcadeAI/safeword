# Retire OpenCode V1 and retain V2 admission authority

**Status:** Proposed under user-authorized scope amendment, 2026-11-06; normal plan review pending.

**Supersedes:** only the OpenCode V1 compatibility/coexistence obligations in [shared host contracts](./shared-host-contracts.md). All other shared ownership, preservation, evidence and admission requirements remain.

The user explicitly retired V1. Remove its active source, schema/config/generated delivery, selection and V1-only proof lanes. Preserve old bytes/results as history, shared primitives still used elsewhere and authored customer/project content. No migration/compatibility framework is required.

V2 2.0.32 CLI and TUI are the sole OpenCode target lanes. The normal installer cannot fall through to retired V1 or silently select unadmitted V2; it reports actionable missing admission until the existing PR4 controller supplies an eligible package. Internal selected-candidate staging remains for bounded proof. Unsupported 1.x cannot receive healthy status or launch V1 conformance. Enrollment and conformance do not substitute for fresh native activation or customer admission.

[Routing investigation and alternatives](../tickets/2ENRH5-consistent-host-contract/evidence/opencode-v1-retirement-routing-decision.md); [user authority](../tickets/2ENRH5-consistent-host-contract/evidence/opencode-v1-retirement-user-approval.json). Independent retirement selection/generation/population oracle and positive V2 controls are required; root owns fresh actual native proof. No SDK/Effect version or policy change is authorized here.

**Existing external assets:** leave previously copied V1 profile files untouched, not automatically removed or represented as inert. Current derivation/selection never emits/invokes them. Exclude retired 1.x from old-package healthy carry-over; status reports unsupported/unprotected with manual removal recovery. V2 install/upgrade/repair/uninstall only act in their current proven-owned scope and cannot claim removal of retained V1 files. No migration/classifier subsystem is required and the unmeasured usage statement is not proof of absence.

**Status observation limit:** unsupported status is keyed to the observed 1.x executable version, not a retained-file ownership classifier. Under V2, leftover V1 files are not detected/reported; evaluate current V2 enrollment/admission/activation/proof only and make no absence/inertness claim about external old code.
