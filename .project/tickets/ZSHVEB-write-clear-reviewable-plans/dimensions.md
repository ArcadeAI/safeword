## Lower-level proof placement after scenario compression

The Execution Plan must name table-driven tests for these variations; they do not each need a separate acceptance scenario because the retained examples prove their observable outcome:

- R1 writing-guide AST and citation contracts: markers inside comments and other inert Markdown nodes must not count as active topic examples; a duplicate required-topic heading with active examples must fail as an extra candidate even though its name is allowed. The retained incomplete/extra-topic scenario proves those rejection outcomes. A table-driven URL matrix must reject credentials, explicit non-443 ports, and non-HTTPS destinations while accepting a parsed inline HTTPS link; the retained cited-guide and citation-free examples prove the outer boundary. Source-aware review test cases must reject private, local, unresolvable, non-primary, or otherwise unsuitable sources and non-contrasting or bloated exemplar pairs; the retained unsupported-citation and alternate-label seventh-topic scenarios prove distinct semantic rejection classes.
- R2 Product Plan parser, resolver, and release checks: every required field hidden in a comment, both incomplete-pair orientations, and all field-marker variants must be rejected. The retained missing-field and incomplete-pair examples prove the outcomes. A parent-classification matrix must reject incomplete-pair, ambiguous, non-Product, child-contribution, repair-required, invalid-marker, and selected-schema-incomplete referenced parents with `invalid-parent-contract`, no continuation, and the parent-specific recovery; the retained schema-incomplete and child-shaped examples prove the distinct outer boundaries. A parent-anchor matrix must distinguish Rule-level `Parent job` (the referenced Rule heading and governed content) from job-level `Parent job` (only the job heading, Persona, and JTBD statement), including separately named Rules in the accepted child plan; editing a bound anchor invalidates continuation while an unreferenced sibling Rule does not. The retained Rule-level invalidation and job-level sibling examples prove both outcomes. A portability matrix applies the retained project-specific-content rejection to every canonical Product Plan template and author/review or shared-decision source, not only the representative full template. A release-check matrix must reject a missing pinned fixture blob, copied fixture bytes whose hash differs from the pin, or a pinned child's persisted parent digest unequal to the canonical digest from the pinned parent blob; the retained release-blocking examples prove release cannot proceed on invalid contract history. A real-Git migrator concurrency test must race first encounters and prove one activation identity and consumer default-branch cutoff with all qualifying plan-family receipts written together, not competing partial boundaries; the retained single-encounter CLI and missing-history scenarios prove the outer behavior. A historical-evidence matrix must separately prove the review-receipt and legacy-phase-evidence forms, latest matching cutoff-reachable commit selection, matching current plan blob, and rejection after a cutoff-reachable return to planning; the retained positive and rejection examples prove their distinct continuation outcomes.
- R3 Implementation Plan field classifier and rubric parser: `Commands to run` and `Current proof results` must be rejected like the retained `Build order` example, while the separate CLI command-contract example remains allowed. Adoption-instance mode must reject one missing-field fixture for each of the thirteen required markers; the retained missing-design-field scenario proves the common failure shape. A retained-obligation removal matrix must separately remove the decision summary, proof-scope choice, confidence limits, architecture applicability, data applicability, Decision Evidence source/version/date boundaries, Recorded Decisions, Design alignment, Persona consequences, Known deviations, Doc impact, and Assessment triggers; each removal must return `implementation-plan-contract-invalid` with that obligation named. The retained complete-plan scenario proves the positive outcome. A continuation-evidence matrix must run both the matching accepted review receipt and cutoff-reachable legacy-phase-evidence forms against unchanged Implementation Plan bytes, and reject a return to planning before the cutoff or a changed plan blob; R2's real-Git scenarios prove the shared primitive's external boundary while R3's retained continuation and changed-byte scenarios prove this plan family's outcome. Zero, duplicate, reversed, nested, or unmatched rubric marker pairs must fail before any required-field scan; the retained rubric-region scenario proves the correctly delimited case, and this parser matrix proves malformed delimiters cannot lend rubric fields to the author region. A portability matrix applies the retained project-specific-content rejection to the template, author-facing contract region, and evaluated rubric.
- R4 target and guide matrices: empty derived targets, package-guide digest mismatch, extension-versus-declared-content variants, and Markdown project-instance identity must receive their specified result or guide binding. The retained caller-override, missing-guide, role-binding, and project-instance examples prove the outcomes.
- R4 manifest and directive parsers: a manifest entry with no discovered canonical source must fail classification with the same result and recovery as the retained unclassified-path scenario. A guide mention in a comment, code block, list item, table cell, or ordinary example must not count as the operative standalone paragraph; the retained role-polarity example proves that outcome. A recovery-inventory matrix must reject duplicate result-and-reason keys and keys with zero or multiple owner-facing recoveries; the retained missing-fixture, undeclared-result, and complete-inventory scenarios prove the outer result/recovery contract.
