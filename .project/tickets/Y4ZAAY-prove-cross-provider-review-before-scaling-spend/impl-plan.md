# Impl Plan: Prove cross-provider review before scaling spend

**Status:** planned

## Approach

The riskiest assumption is that Arcade's production review path can use a genuine OpenAI Responses tool loop for both repository reading and finding verification while retaining enough native evidence to prove every paid turn's route and cost. The cheapest proof is the first slice: a two-turn fixture review through the real `createRunnerExecutor` wiring, with only HTTP faked, that reads a repository file, reports a finding, verifies it, and retains two distinct native Terra response envelopes. It must fail if the Anthropic loop runs, either envelope is missing, or model/service-tier identity is relabeled.

Build in this order, keeping the next slice dependent only on green behavior from the prior slice:

1. **Genuine OpenAI Responses loop and call evidence (Arcade integration).** Add an OpenAI-specific `AgentRunner` beside the existing Anthropic loop, translate the current repository tools and terminal `report_findings` tool to strict Responses function definitions, replay complete `response.output` items plus `function_call_output` items, and request `gpt-5.6-terra` with `service_tier: "default"` on every turn. Add one provider-turn recorder interface shared by the loop and OpenAI verifier so a caller can durably record pre-dispatch intent and retain the exact native response body, response/request ID, stage, requested route, returned model, returned tier, and native usage. The ordinary production runner may omit the recorder for backward compatibility, but the canary factory requires it at construction and exposes no unrecorded dispatch method; missing recording remains a post-hoc validation backstop, not the primary control. Do not rewrite the established Anthropic loop or infer provider identity from configuration labels.
   - Primary proof: integration test through `createRunnerExecutor`, real detector/runner/toolset and real temporary Git repository, with only HTTP and time faked. This is the highest practical scope and proves repository reading, reporting, verification, and entry-point wiring together.
   - Supporting proof: focused unit tests for malformed/truncated Responses envelopes, quiet turns, tool budget, report termination, multi-turn usage summation, and preservation of reasoning output items required on later turns.
   - Covers R1's accepted-fixture, paid-route mechanics, provider-relabeling, turn-count, request-ID pairing, mixed-provider, zero-turn, and standard-tier cases.

2. **Ticket-local evidence contract and frozen pricing (Safeword units).** Add `terra-canary-evidence.ts` with strict parsers for attempt intents, request-start/completion records, immutable upstream initialization/start/completion receipts, raw OpenAI Responses envelopes, trusted corpus registration/provenance, and diagnostic result manifests. Add pure integer-picodollar pricing over native usage details using the rate table in `spec.md` as the single policy authority. The validator recomputes the corpus digest and requires native OpenAI `gpt-5.6-terra` with returned `service_tier` exactly `"default"`; the request pins the same literal and OpenAI documents it as standard processing. It requires `usage.input_tokens` and `usage.input_tokens_details.cached_tokens`, permits only `usage.input_tokens_details.cache_write_tokens` to be absent/zero, requires `usage.output_tokens`, and records optional `usage.output_tokens_details.reasoning_tokens` as zero when absent because reasoning is already included in the charged output total. Unknown native detail keys are retained verbatim but do not invalidate cost unless they replace or contradict a price-affecting required field. Official prompt-caching documentation establishes that cached and cache-write counts measure prompt-input subcomponents; the validator rejects negative or over-total component arithmetic and derives uncached input as `input_tokens - cached_tokens - cache_write_tokens`.
   - Primary proof: table-driven unit tests because parsing, exhaustive reason collection, integer arithmetic, and the 272,000 boundary have many fast deterministic combinations.
   - Covers all R1 rejection/provenance examples, R2 detailed-usage and exact-threshold examples, and R3 trusted-registration/diagnostic guards.

3. **Crash-safe single-writer canary controller (Safeword integration).** Add `terra-development-canary.ts` that owns one isolated output directory with append-only JSONL journals: immutable initialization marker, attempt intents, provider request starts, provider completions/raw bodies, and derived result manifests. The live command acquires an `O_EXCL` lock file for the full initialize-or-run critical section and refuses a second process; a stale lock is never guessed away automatically. Initialization first posts and verifies the upstream consumption receipt and zero head, then creates and fsyncs the immutable marker, zero-attempt journal, and zero-cost journal, syncing the directory after each create. Before each attempt, the credentialed parent reloads and reconciles every local byte against immutable upstream receipts, posts and verifies the next sequenced start receipt, then appends/fsyncs local intent before launching the paid child. The child has GitHub/write credentials removed and OpenAI SDK/HTTP automatic retries set to zero. After it exits, the parent persists raw evidence locally, posts and verifies exactly one completion receipt bound to the attempt ID, sequence, response digest, native usage, and exact aggregate picodollar cost, and only then admits the new complete head. A remote start without a completion or any unavailable/disagreeing head fails closed; local ledger deletion therefore cannot reduce attempts or spend. Only a downstream failure after complete, priceable provider accounting may return to the controller for a separately authorized new attempt. A retryable OpenAI/transport error without native priceable usage leaves the started attempt incomplete, makes no hidden or controller-owned retry, and permanently blocks that output identity with `incomplete-cost-accounting`. A crash after any remote write deliberately fails closed until the exact local/remote state is reconciled; state is never recreated as zero.
   - Primary proof: integration tests over real temporary directories and a fake upstream/HTTP process boundary; restart tests instantiate a new controller over the same bytes. This proves persistence and mutation behavior without paid calls.
   - Supporting unit proof: the pure decision function covers same-process/resume equality, combined reasons, duplicate intents, partial bootstrap, incomplete cost, retries, and exact cap behavior.
   - Add ticket-local Cucumber selection wiring and a contract test proving both the repository default and CI command exclude `@paid-canary` with `not @paid-canary`. Independently prove that even an explicitly/accidentally selected paid scenario cannot dispatch without durable authorization.
   - Covers every R2 scenario, including the two-turn-one-attempt rule, retry-as-new-attempt rule, initialization/reset/plant/forge cases, request-before-intent and intent-before-completion crash windows, exact/below/above $15, cap combinations, and missing live authorization. Authorization rejection fixtures include local-only flags, non-allowlisted authors, foreign canonical repositories, edited or duplicate comments, replay across output identities, and mismatched corpus/adapter/route/limit bindings. The exclusive lock is separately unit-tested defense in depth, not a feature-scenario claim; concurrent live execution remains out of scope.

4. **Diagnostic isolation, trust root, and corpus provenance (Safeword integration).** Reuse the registration blob and digest already reachable from protected `origin/main` commit `eca10ca59c40e108695c484fd19260e1c1bd0784`, plus its existing unedited GitHub anchor comment `5254523549` authored by the allowlisted maintainer `TheMostlyGreat`. After both code paths are durably tagged, the maintainer adds exactly one new unedited authorization comment with a random ID that binds that registration, both adapter and harness tags/commits, output identity, route, limits, receipt budget, and policy. The harness reads the public GitHub REST API over HTTPS and requires the canonical repository/comment IDs, exact allowlisted author and `MEMBER`/`OWNER` association, `created_at === updated_at`, the registration commit reachable from `origin/main`, and byte-for-byte agreement among the committed registration, existing anchor, authorization, and sequenced immutable receipts. Missing, foreign, edited, forked, self-supplied, unreachable, duplicate-same-ID/sequence, or disagreeing evidence uses the existing unavailable/unreadable fail-closed path. A mistaken unused authorization is abandoned and replaced with a new ID; correction after consumption is out of scope and requires a newly authorized output identity. The credentialed parent may post only the bounded initialization and per-attempt receipts authorized for that identity; the paid child receives neither GitHub nor other write credentials, so model-executing code cannot author or alter its trust evidence. This is a repository-governance trust boundary, not cryptographic protection from a compromised repository administrator.
   - Resolve corpus role only from that authority record keyed by a locally recomputed digest and copy its author-provenance field verbatim into each result. Emit `evidenceRole: "development"`, `diagnosticOnly: true`, both pinned code identities, frozen model/tier/pricing policy, and complete route/accounting decisions.
   - The confirmatory guard performs the same two-channel lookup and digest recomputation. It rejects every development artifact regardless of successful mechanics, while admitting all four independently anchored confirmatory fixtures—including those with a stale local development marker—so a deny-everything implementation cannot pass.
   - Primary proof: integration tests with repeatable mixed-case provenance fixtures and a real copied corpus manifest; only upstream lookup is faked.
   - Covers all R3 scenarios and the R1 legacy-provenance cases. A provenance-invalid attempt is never refunded: complete native Terra/default usage is still priced exactly once into observed spend, while incomplete or unpriceable usage marks accounting incomplete and blocks later dispatch.

5. **No-cost preflight and durable pins.** Run the targeted Arcade suite, Arcade full test/typecheck, Safeword ticket-local tests, the tag-selection contract, Safeword full test/build/typecheck, and the existing diagnostic/confirmatory preflight. Commit and push both isolated code branches. Create and push annotated non-release tags for both exact commits, update the development preflight manifest to both tag/commit identities, and prove fresh clean checkouts resolve from their canonical remotes and reproduce all no-cost verification. Neither research-code pin requires a merge: each canonical remote must advertise the exact annotated tag object and peeled authorized commit named by the maintainer authorization, while the corpus registration remains independently reachable from protected `main`. Only after both durable pins exist does the maintainer create the one-time authorization comment described in slice 4. The live launcher refuses dirty checkouts or commit/tag mismatches, completes remote checks before durable attempt start, and fixes the per-attempt 25/40/360-second policy. No secret is loaded before this step is green; default/CI tag exclusion and the authorization guard are independently tested barriers against paid dispatch.

6. **One authorized paid canary.** From the two clean tagged checkouts, create a fresh isolated live-output directory, add the one-time upstream initialization authorization bound to both pinned commits/tags, corpus digest, model/tier, 10-attempt/$15 policy, receipt budget, and output identity, consume it during explicit initialization, then load `OPENAI_API_KEY` through 1Password without printing it. The parent retains only the GitHub credential needed for bounded receipt writes; the paid child receives only the OpenAI credential and has automatic retries disabled. Execute sequentially until ten attempts have started or a completed attempt leaves spend at/above $15 or either local/upstream accounting becomes incomplete. Retain the threshold-crossing attempt, make no later request, and report mechanics only; do not score reviewer quality or unlock confirmatory spend.
   - Primary proof: the single `@paid-canary` E2E scenario plus post-run offline validation of every retained raw envelope, intent ordering, cost sum, provenance, and diagnostic-only guard.

## Decisions

The `/figure-it-out` investigation framed two decisions: how to add a genuine second-provider tool loop without making the existing runner ambiguous, and how to make a paid cap survive retries/crashes without a new service. Research domains were (1) OpenAI Responses function-call replay and reasoning-item preservation, (2) provider-native route/usage observability, (3) the existing Arcade `AgentRunner`/provider seams, (4) exact billing arithmetic, and (5) crash consistency and upstream trust. The evidence favors small explicit adapters and append-only evidence over a broad abstraction rewrite.

| Decision | Choice | Alternatives considered | Rejected because |
| -------- | ------ | ----------------------- | ---------------- |
| Repository-reading implementation | A separate OpenAI Responses loop implementing the existing `AgentRunner` contract | Rewrite the Anthropic loop into one provider-neutral state machine; shell out to Codex CLI | A generic rewrite expands risk before the canary and still needs provider-specific replay rules; a CLI hides native envelopes, route, tier, and exact usage needed for audit. |
| Multi-turn state | Replay the complete returned `response.output` plus matching `function_call_output` items in the next request | Replay only function calls; depend only on `previous_response_id` | OpenAI requires reasoning items returned with tool calls to be passed back for reasoning models; complete replay is fixture-testable and keeps the evidence self-contained. |
| Provider evidence | Shared pre-request/post-response recorder at the external HTTP boundary, required by the canary factory | Infer calls from final report/usage totals; return only normalized token counts | Totals cannot prove every paid turn, pairing, ordering, actual model, or service tier, and normalized usage discards price-critical native details. |
| Verifier route | Keep the existing verifier contract but use an OpenAI verifier instance wired to the same observer | Reuse Anthropic verification; skip verification during canary | Either would violate the requirement that every paid turn use Terra and would leave the route inventory incomplete. |
| Durable accounting | Ticket-scoped append-only JSONL journals reconciled against immutable upstream initialization/start/completion receipts, plus an immutable marker and single writer | Local-only files; mutable aggregate JSON; SQLite | Local-only state cannot prove deletion did not reset the cap. The bounded upstream receipt chain supplies a monotonic head, while local raw envelopes retain detailed audit evidence. |
| Initialization trust | Existing protected-main registration plus its unedited anchor and exactly one unedited allowlisted-maintainer authorization comment; consume its one-time ID upstream before local marker/zero-state creation | Trust local marker; trust one mutable issue comment; silently rebuild missing state; consume after local creation | Local state can be planted/deleted, one mutable channel can self-attest or drift, rebuilding resets spend, and local-first can leave reusable upstream authority after a crash. Upstream-first may brick a partial bootstrap but never permits duplicate spend. |
| Live ownership | `O_EXCL` output lock held across reload, decision, dispatch, and completion | Document single-writer as a precondition; lock only individual appends | Two processes can otherwise both observe attempt nine and dispatch attempt ten. |
| Cost representation | Integer picodollars with per-turn tier selection from native detailed usage | Binary floating point; provider dashboard estimate | Floating point makes exact equality unsafe; the dashboard cannot be causally paired to retained turns or used offline. |
| Confirmation boundary | Recompute corpus digest and resolve role/provenance from the trusted registration on every validation | Trust artifact path/digest/role fields | Self-declared artifact metadata could promote contaminated development evidence. |

### Implementation inspiration

| Reference | Pattern used | Decision informed |
| --------- | ------------ | ----------------- |
| [OpenAI Responses migration guide](https://developers.openai.com/api/docs/guides/migrate-to-responses) | Responses is the recommended new agentic API and supports multi-turn tool use | Use a genuine Responses loop rather than extend the legacy Chat Completions adapter. |
| [OpenAI function-calling guide](https://developers.openai.com/api/docs/guides/function-calling) | Preserve response output, append `function_call_output`, and replay reasoning items for reasoning models | Replay complete native output and test a real multi-turn repository read. |
| [GPT-5.6 Terra model reference](https://developers.openai.com/api/docs/models/gpt-5.6-terra) | Responses support, 272K long-context boundary, cache-write multiplier, and Terra token prices | Freeze the exact route and implement per-turn integer pricing. |
| [OpenAI API pricing](https://developers.openai.com/api/docs/pricing) | Standard processing prices and cached-input accounting | Validate returned standard/default service tier and native detailed usage before assigning cost. |
| [OpenAI prompt-caching guide](https://developers.openai.com/api/docs/guides/prompt-caching) | Responses expose `cached_tokens` in `usage.input_tokens_details`, GPT-5.6 adds `cache_write_tokens`, and both measure prompt-input subcomponents | Parse the documented fields, normalize only absent cache-write usage, retain unknown additions, and reject impossible component totals. |
| `tools/pr-review/src/runner.ts` and `tools/pr-review/src/eval/development-benchmark.ts` at pinned branch `codex/cwgyh0-dev-benchmark-adapter` | Existing injectable `AgentRunner` and real-runner benchmark executor | Add the smallest explicit adapter/observer seam instead of replacing production orchestration. |

Recommend **the separate OpenAI `AgentRunner` plus shared provider-turn observer** because native, per-turn evidence is the load-bearing requirement and cannot be reconstructed from a normalized final report. A provider-neutral rewrite is attractive for eventual product reuse but loses on blast radius before the first paid proof.

**Premortem:** Assume this design failed after the canary—the most likely cause is a changed OpenAI field replacing a price-affecting documented field, so the parser requires the documented fields, retains harmless additions, rejects contradictory component totals, and records the exact raw envelope for audit.

**Next:** finish the formal ticket suite once the repository-wide single-Vitest lock is free, then run the complete no-cost preflight from fresh clones. Only after that is green, commit and push the exact harness code and create the annotated adapter and harness evidence tags; do not load real secrets or create the permanent authorization comment before those durable pins are verified.

This honors the accepted **Advisory PR Review as a Split-Privilege Evidence Pipeline** decision in `ARCHITECTURE.md` by using an explicit OpenAI Responses implementation and configured provider/model identity, the **Frozen Transcript Fixture Testing** decision by retaining realistic native envelopes, and the architecture's existing typed-runner/test-boundary pattern. No ADR update is warranted: the implementation is ticket-local research tooling plus an additive adapter on a non-main branch. The pinned-adapter qualification remains an explicit manual proof because this repository has no least-privilege credential for the private collaborator repository; promotion to a supported release invariant requires a separately reviewed provenance design. The deliberately durable tag/comments remain evidence anchors.

## Known deviations

- The live controller is ticket-local research code rather than a published CLI command; that is deliberate because this slice proves the instrument before productizing it.
- The live proof adds two annotated non-release tags and a bounded permanent public trail: one authorization, one initialization receipt, and at most ten start/completion receipt pairs. The maintainer performs those writes only after no-cost verification; the user's explicit live-canary authorization in this session is the owner sign-off. They preserve auditability and are not reversible like the ticket-local outputs.
- Initialization consumes upstream authorization before creating local state. A crash in that narrow window can permanently brick this canary and require a new explicitly authorized output identity; this fail-closed operational cost is preferable to silently permitting duplicate spend.
- The live implementation is single-writer and refuses a second process through an exclusive output lock. Automatic stale-lock recovery and distributed ownership are outside a ten-attempt local canary.
- The legacy corpus is already contaminated by the old scorer defect and has legacy author provenance. Its results remain diagnostic-only even if every mechanical check passes.
- Direct regression execution for the unchanged Anthropic route requires the external pinned adapter checkout. The retained qualification snapshot is historical evidence of that manual run, not an independently authenticated CI proof.
- GitHub issue comments are a repository-governance trust root, so an untrusted marker-shaped comment can deliberately force the canary into its unreadable fail-closed state. Recovery requires a newly authorized output identity; the public issue is not an availability boundary against hostile commenters.
- The ticket-local launcher validates the frozen corpus fields and paid-input digest, while the pinned external adapter remains responsible for proving the target checkout head/base pair before provider execution. The retained qualification is historical evidence for that dependency, not a self-contained proof in this repository.

## Doc impact

No customer documentation changes. The pinned paid-canary qualification is manual ticket evidence and is deliberately not presented as an independently authenticated main-CI gate; the ticket changes no customer-visible README, website, installed guide, or CLI command.

## Assessment triggers

- Reuse by a second benchmark, promotion into the published PR-review product, or any need for concurrent/distributed workers.
- A canary beyond ten attempts, an observed-spend limit above $15, or any new paid retry policy.
- A new model, service tier, endpoint, pricing table, 272K boundary, or change to OpenAI's Responses/usage schema.
- A need to recover automatically from partially consumed initialization rather than deliberately bricking the output identity.
- Creation of the fresh Claude-authored confirmatory corpus or any request to use these results for confirmatory estimates.
- Promotion of the ticket-local CI qualification into a supported release invariant.
