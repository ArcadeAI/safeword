# Bounded completion-evidence recovery

**Status:** planned

**Planned on:** 2026-10-11

## Approach

One compiled profile defines the accepted case set. A fixed observer executes a committed candidate and authenticates its full report and inputs. Reviewers certify a recomputed summary; the completion gate requires those fresh receipts before returning two views: unchanged historical evidence with one exact erratum, and current completion with every deferred case still unverified. Shared local closing hooks consume that gate; they grant no authority themselves.

This task's behavior authority is ticket.md's accepted scope and done_when, supplemented by the original 5F5ZZA spec, plans and feature. It introduces no separate Product Plan or new persona promise. The user approved current certification without invented historical RED and exclusion of exactly 33 deferred cases. Preserve CKWE2D and the original checked ledger rows. No merge, promotion, release or installed-cache override is authorized. This plan records design; implementation progress and commands belong in ticket.md's work log.

Architecture applicability: required. The coordinator's new kind, signing domain and shared closing view follow the recorded [exact recovery decision](../../../ARCHITECTURE.md#exact-completion-evidence-recovery-for-5f5zza). This is a bounded exception, not a new general completion protocol.

Measurement applicability: skip: no quantitative product or performance promise is introduced. The 142 active and 33 deferred identities are exact correctness constraints, not measurement targets.

Lifecycle: commit product/test sources, observe, write manifest/summary, certify, commit audit-only artifacts, close. Certification binds the exact audit bytes before their commit; committing unchanged audit bytes preserves both the projected product identity and receipt fingerprints. Arbitrary new files do not. Signed observations and full reports live in runtime-owned unique paths under .safeword/state/reviews; the committed manifest/summary are the reviewable audit record. The gate recomputes the bounded summary from authenticated full report bytes, avoiding a 1.9 MB review target.

Data applicability: required. The compiled profile owns scope and historical identity; the signed runtime observation owns execution evidence; manifest and summary are reviewable references, never independent authority. Census and reconciliation files are inventory, not proof. These versioned JSON records use existing project-local ownership and private-key access. Review context crosses the existing authorized reviewer boundary; no new export service or collection policy is introduced. No personal-data model or compliance change is added.

An observation progresses from incomplete preparation to retained failed evidence or an authenticated passing record. Product/input changes make it stale; a new attempt coexists in a unique directory. The fixed manifest selects exactly one observation, so the gate never picks an arbitrary latest report. Each file is durably written; there is no multi-file transaction. Report and lock parts precede observation and tag; the manifest precedes summary. Missing, partial or mismatched files deny credit. A crash before the tag grants nothing; a crash between manifest and summary leaves the gate denied. A retry creates a new directory and republishes the pair, retaining earlier failure evidence. A crash before certification or the audit commit requires resuming that step against unchanged bytes, never reconstructing a successful report.

Retain observations, reports, parts and receipts through epic acceptance and any later evidence audit; this task adds no automatic deletion. Ordinary future cleanup may remove them only after recovery is no longer relied upon. No migration or historical backfill occurs. Retirement or rollback removes recovery credit and restores ordinary blocking; it preserves original ledgers and retained records and does not rewrite a previously closed ticket. Such a ticket must be revalidated before a new completion action. Older runtimes have no recovery authority and fail closed; their whole-ledger fingerprint mismatch continues to block dependent GREEN annotations until separately authorized trusted deployment.

concatenation to equal the observed and current complete lockfile. Review
contexts cover both parts. This represents the same required input; it does not
exclude the lockfile, raise packet limits or introduce a generic chunking system.

Introduce the bounded ledger-recovery review kind in the existing coordinator. Its installed rubric requires actor-boundary fidelity, real rejection controls, source fidelity, no historical RED claim, the sole exact erratum and the exact unverified deferrals. Certification targets bind only manifest, summary and contract; other excluded work-log and verify artifacts may change during ordinary closing. Completion-hook deadlines cover compact validation, never expensive observation.

## Decisions

Use one exact profile rather than arbitrary-ticket eligibility; append-only corrections rather than rewritten history; a distinct view rather than VERIFIED's blanket suppression; a typed certification review rather than a generic review whose context cannot instruct it. Add no dependency, signer or generic proof engine.

Two exact lockfile parts preserve the existing file limit; increasing that limit would widen every review packet's trust and capacity boundary. A dedicated review kind makes the six confirmations enforceable; an ordinary quality-review label cannot establish typed certification. A detached checkout prevents preparation from changing the reviewed working tree; in-place execution would mix installation effects with candidate evidence. Recomputing a compact summary keeps complete reports authoritative while avoiding oversized reviewer packets. Each choice can be retired with this exact profile; reverting it removes credit rather than migrating historical proof. No third-party code is copied and no new license or security dependency is introduced. The user, private key and dependency host remain trusted.
