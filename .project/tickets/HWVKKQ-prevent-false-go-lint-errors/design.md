# Revised proposal: trustworthy Go post-edit lint for #4733, #5105, #5427

Status: proposed design, not implemented. This review authorizes no production edit. The work is correcting package/module context and trustworthy feedback after Go edits. Do not widen this into general linter management or dependency upgrades.

## Execution and scope

Canonicalize the edited file and supplied project root, then use path.relative containment (not string startsWith). If the file resolves outside the project, return an explicit warning and execute neither lint nor formatting. For an in-root Go file, run golangci-lint with command-local cwd = canonical edited-file directory and nonrecursive package target `.`. Never process.chdir; pass cwd explicitly to the capture helper as well as formatter. Retain inherited Go environment/build tags/tests/toolchain/workspace behavior; do not force GOWORK=off, synthesize go.work, or select other modules. Keep existing v2/missing-tool checks.

Accept PACKAGE diagnostic scope deliberately. Report all findings in the affected package, including existing lint debt in siblings. Do not lint unrelated packages recursively, filter away typecheck failures, claim the findings were introduced by this edit, or tell the agent that every finding is in the edited file. This is the native Go analysis unit; JSON filtering and diff-based debt tracking are excluded from this fix.

Run formatter once on the exact canonical edited file and lint the package once afterward WITHOUT --fix. Go lint autofixes are intentionally removed; formatting remains automatic. Do not retain a file-scoped --fix pass (incomplete package), nor use package-scoped --fix (would mutate siblings). This is an explicit behavior tradeoff for bounded edits, not a claim that fmt replaces lint fixes. Update Go comments/help accordingly. Other languages retain current behavior.

## Customer configuration compatibility: freeze context once for every mode

One normalization mechanism owns every config mode; do not special-case only wd. Define `originalCwd` as the canonical process.cwd() at entry to lintFile BEFORE any new child cwd is chosen. Each host already changes to its project/workspace before this call: Claude/Codex use the resolved project directory, Cursor uses workspace_roots[0]. Define projectRoot from the supplied lintFile argument and resolve Go's managed config from that root at call time, never the module-initialization cached projectDir. A Cursor launch directory that differs from its selected workspace must use that selected workspace's Go config and originalCwd. Other-language config caching is out of scope.

Resolve the selected config before moving cwd: .safeword/.golangci.yml under supplied projectRoot wins; otherwise preserve the prior native precedence (originalCwd first, then edited-file directory/ancestors, then home) and supported YAML/JSON/TOML filenames. Pin the result by absolute path. Malformed config stays an infrastructure warning; do not silently substitute defaults. No config means explicit --no-config plus the existing missing-Safeword-config warning; no unconfigured path policy needs preservation.

For a selected config, compute its ORIGINAL base B from that configuration and originalCwd, using upstream's rules: cfg/default => original config directory; wd => originalCwd; gomod => parent of go env GOMOD obtained with inherited environment and cwd=originalCwd; gitroot => git rev-parse --show-toplevel with cwd=originalCwd. Freeze the returned canonical B before running from the package directory. A failed base lookup must be an explicit warning; do not guess a new base or report clean lint. Retain the actual native result when meaningful, including an outer module/repository base while targeting a nested module/repository. The package-loading cwd changes; the configuration's matching base does not.

For ALL selected configs materialize one effective JSON config with run.relative-path-mode=cfg DIRECTLY in B. Exclusive-create a random .safeword-go-lint-<uuid>.json with mode 0600; keep every rule/key except the explicit location-sensitive normalizations here. cfg now resolves to B in every case, so exclusions, custom-plugin base paths, formatter exclusions and ${base-path} keep their old meanings regardless of the edited package's module/git root. This intentionally replaces the previous native-mode exemption. Original config bytes remain untouched. The extra file is necessary whenever preserving cwd-derived semantics is required; do not reintroduce mode-by-mode bypasses until equivalence is proven.

Relocation may change ${config-path}, so freeze that placeholder to the original config directory ONLY where upstream interpolates it: depguard.rules.*.files entries, gocritic.settings string values recursively, and goheader.template-path. ${base-path} retains B. Do not blindly substitute arbitrary rule text. For raw cwd-relative built-in file resources, normalize before cwd changes: goheader.template-path becomes absolute against originalCwd; each comma-separated gocritic.settings.ruleguard.rules file/glob becomes absolute against originalCwd after placeholder expansion (preserve globs and list membership). Absolute entries remain absolute. Configured output file destinations (excluding stdout/stderr) also become absolute against originalCwd, so a cwd change does not relocate customer reports. This does not promise to virtualize arbitrary third-party plugin filesystem operations.

Parser/runtime decision: put the Go executor and this normalization in one internal `hook go-lint` CLI action, called by the shared lintFile through safewordCli(projectRoot) using the call-time root, never the module-cached resolver root. Use the returned command/args/cwd as declared; an older pinned CLI that lacks hook go-lint produces an actionable version/helper warning, never a fallback to the broken per-file invocation or a false clean result. Reuse production dependencies yaml and smol-toml for YAML/TOML, JSON.parse for JSON; add no dependency and no new Bun API/minimum. Preserve YAML merge keys with merge:true and type fidelity; use YAML AST/schema-aware handling for legacy boolean forms, leaving scalar forms intact when safe and issuing a warning if a construct cannot be faithfully represented. Test merge-key and legacy boolean inputs against the real linter. No unsupported input is silently accepted with dropped keys. JSON serialization must reject non-finite/otherwise lossy unsupported values rather than deleting them. The CLI action owns subprocesses and temporary-file lifetime, and returns the existing warnings/errors shape plus Go message metadata. It introduces no second config policy and no unpinned CLI. The resolver's EXISTING pinned-package fallback may download the pinned CLI on first use; this is an explicit cost, not a no-network claim. Missing/unrunnable helper yields a warning, never falsely successful lint.

Lifetime: try/finally cleanup after normal completion and ordinary lint/format/parse/spawn errors; only remove this invocation's exact temporary file. Also install SIGTERM/SIGINT/SIGHUP handlers in the Go executor that terminate its linter child, remove its exact temporary config, restore signal disposition and terminate with the same signal. Make cleanup idempotent so finally and signal paths cannot race into deleting another invocation's file. Test each signal in a real child-process harness. Concurrent invocations have distinct exclusive filenames. Creation or cleanup failure is an actionable warning; never fall through to a changed-base config. No install, staging, permanent config modification, or sibling source rewrite occurs. Cleanup is best effort under ANY host-initiated termination: SIGKILL, abrupt host/runtime death, signal races or cleanup failure can leave an untracked .safeword-go-lint-*.json in B, and git add -A can include it. Never claim all host timeouts run finally or that signal handlers make cleanup guaranteed. This is an explicit residual limitation, not a justification for broad stale-file deletion or new persistent cleanup infrastructure in this fix.

## Feedback contract

Extend LintResult minimally with optional diagnostic context/message metadata for Go. post-tool-lint consumes it, preserving other-language wording. Go's message is: `Go lint findings for package <absolute-directory> after editing <absolute-file>. These findings may predate this edit; sibling files were not auto-fixed.` Then include diagnostics with absolute paths using --path-prefix B (or the package cwd with --no-config). This flag and filepath.Join behavior exist in v2.0.0; do not require the newer --path-mode abs flag. Normalize report output to captured text on stdout while preserving customer report destinations against originalCwd; bound the additionalContext payload to 16 KiB with an explicit truncation notice; omit a generic rerun command because running the original config directly from the package directory would lose the frozen context. Never say truncated output means only those issues exist. Keep package-loading/typecheck diagnostics, even when they point to a sibling. Do not say after auto-fix. A formatter or loader failure is a warning and must not become a clean-success claim. Ensure warnings are retained even when errors also exist (the current wrapper drops warnings in that case).

Claude and Codex consume post-tool-lint.ts; Codex currently calls it via runPackagedHook. Test both entry boundaries. Cursor currently ignores LintResult and only benefits from formatting; preserve that existing delivery behavior rather than adding a new Cursor notification mechanism. Test its package cwd/config selection and file-only formatting through its real adapter. No claim that Cursor now displays diagnostics.

## Proof required before implementation is complete

Real golangci-lint + Go fixtures must establish:

- same-package _test.go references sibling declarations: current hook fails, revised hook passes;
- nested module internal import: current hook fails, revised hook passes;
- go.work sibling dependency: preserve workspace resolution;
- broken unrelated package: not visited; genuine broken sibling in same package: retained with correct package message and absolute source path;
- existing sibling ordinary lint debt: reported explicitly as package findings, edited file never blamed; bytes of every sibling unchanged;
- fixable non-format violation: remains reported, while formatting of the edited file is applied; no run --fix invocation;
- explicit wd exclusion/formatter exclusion: same effective result before and after cwd change, including a negative control proving the exclusion actually suppresses a real finding;
- relocated ${config-path} depguard selector: a real forbidden import is reported both before/after; gocritic and goheader interpolation and relative goheader resource retain original meaning;
- cfg/default with relative goheader template and ruleguard glob resources: naive package cwd loses the original resource while normalized config retains it; gomod with nested modules and gitroot with nested repositories/submodules: an original-base exclusion suppresses a real finding both before and after normalization, while naive package cwd reports it;
- fallback root/nested/home/no-config precedence, invalid config, no-config warning, TOML/JSON parsing, YAML merge-key and legacy-boolean semantic equivalence;
- symlink root canonicalization; outside-root symlink executes no commands; Cursor launch cwd differs from its selected workspace and the Go config comes from that workspace;
- temporary config cleanup after success/error and SIGTERM/SIGINT/SIGHUP, child termination and preserved signal exit, exclusive concurrent names, creation failure surfaces warning; document SIGKILL/host-death residue;
- tests assert actual subprocess cwd AND argv, not only a regex ending in `.`; assert helper resolution uses call-time projectRoot and unrecognized hook go-lint is a warning;
- final Claude and Codex output includes BOTH config/formatter warnings and lint errors when both exist; non-Go output remains compatible;
- build tags/platform-specific edited files: use inherited selection. Do not advertise all-file/all-platform verification; package clean is not proof a build-excluded file was analyzed. Empty/non-package/only-external-tests/no-module cases must either yield native valid package output or an explicit loader warning, never synthesized success after nonzero/empty linter failure.

Do not install tools from tests. Provide a CI matrix with matching Go toolchains and golangci-lint v2.0.0 (oldest accepted v2) plus the current v2.13.2; fail the integration lane if either tool is missing. Prove the full normalization/output semantics on BOTH linter versions, not just flag presence. If compatibility fails, resolve it before implementation completion rather than silently raising the minimum. Local skips must be labeled as missing integration proof. Unit stubs log pwd as well as argv. Sync template changes using safeword install; regenerate all required surfaces using scripts/dev and check-generated-surfaces --fix, never edit generated mirrors directly.

## Evidence, limitations, and tradeoffs

Initial real experiments: go test . passed; current lintFile on _test.go gave undefined Value; repository-cwd source-file lint lost nested module imports; repository-cwd directory target failed; package cwd/run . and module-root/relative package both passed. Workspace dependency resolution worked; unrelated broken package stayed excluded; genuine targeted-package typecheck failure remained visible. These are source-hook and local tool tests, not proof of all host adapters.

New experiment: a real govet finding suppressed by ^apps/engine/internal/service/ under wd reappeared with naive package cwd; an effective cfg-mode config placed at the old wd preserved the exclusion. A depguard file selector using ${config-path} with a forbidden fmt import produced the same real error before and after freezing config-path to the original config directory. Paths were canonicalized and both outputs explicitly named the forbidden import; earlier glob selectors containing unnormalized .. did not discriminate and are not evidence.

The single context-freezing adapter is necessary compatibility complexity for the observed wd/gomod/gitroot and raw-resource regressions. Rewriting all configs permanently, imposing gitroot, synthesizing go.work, filtering all package results, or disabling analysis would trade correctness for fewer lines. No new library is required: yaml and smol-toml are already production dependencies (packages/cli/package.json). Filesystem inability to materialize an effective config is an honest warning/skip, not false lint feedback.
