## Smallest implementation

### 1. Freeze one exact recovery contract

Prepare a separate recovery feature; leave T3E4NS's recovery exclusion intact.
Its accepted behavior must cover success, wrong scope, forged/incomplete proof,
stale inputs, missing certification and unchanged history. This task proposes
that behavior; it does not declare the new contract independently approved.

Bind ticket identity, accepted scope/Rules, feature, proof map, ledger and all 37
compiled cases to a reviewed profile for a committed current-main candidate.
Derive a new baseline from that candidate, without removing provenance checks
merely to make the old profile pass. Preserve all 33 historical deferred objects
and owners; a matching count cannot authorize swapping case identities.

Those 33 objects are an immutable historical snapshot from #5857, not a claim
that its digests describe main's current scenarios. The inventory also hashes
main's original 5F5ZZA feature and ledger. Before any profile adopts current
exclusions, cross-reference the historical objects with those sources and the
four owning deferral tickets, record moved/changed/unmapped cases, and review the
reconciliation. Do not silently translate old identities into new authority.
Empty historical stepDigests confer no extra binding; preserve them as observed.

Freeze the current spec/Rules, scenarios, proof map, unchanged historical ledger
and resolved execution inputs. For ticket.md, bind identity, scope, out_of_scope,
done_when and parent linkage separately from status, phase, timestamp and Work
Log. New manifests, summaries and verification records are audited outputs,
not product inputs; their exact reviewed bytes remain bound to certification.
delivery-state.md's inventory hash is a research snapshot, not a promise that
the file can never change. An output actually loaded during execution becomes
an execution input and cannot use a lifecycle exemption. The recovery feature
must specify this projection before implementation; no whole-ticket exemption.

### 2. Observe one fixed local proof lane

Adapt the existing isolated runner and #5857 observer concept to the 11 declared
normal Vitest files plus the proof-map gate. Root Cucumber acceptance excludes
`@proof.vitest`, so it cannot observe these 37 cases.

The observer accepts only the bounded ticket identity, never caller-selected
commands, reports, filters or success flags. Execute a clean committed candidate
in an isolated checkout through scripts/dev. Bind product identity, resolved
test/support files, config, lockfile, launcher, toolchain and actual runtime.
Retain the exact command, assertion results, exit status and full report.
Authenticate the observation under a distinct purpose using existing keys and
durable writes. Partial, failed, skipped, interrupted or unparseable required
proof grants nothing; retries retain earlier attempts separately.

Map each compiled case to actual assertion results, including parameter rows.
The current proof registrations are the starting point, not semantic coverage
certificates. If a row cannot be supported, report it as unsupported rather than
invent an assertion or weaken its accepted meaning. Unrelated skipped tests in
a selected file must be distinguished from a skipped required proof assertion.

Return separate historical and current-certification views. Do not rewrite any

Shared gate edits remain excluded. Until an accepted closing integration exists,
even a valid certificate is evidence only; ordinary closing checks still block.
Do not bypass T3E4NS's unfinished planning stages. Specify how those obligations

## Verification sequence

1. Reproduce the 14-block/37-case inventory and exact 33 deferrals; run the mapped
   proof files and normal registration gate without providers. This is current
   characterization, not recovery or historical RED.
2. For the new observer, obtain genuine public-CLI RED for missing behavior. Use
   real parsers/storage/signing and mock only process boundaries. Test wrong
   ticket, failed/partial report, missing case/input and incomplete writes.
3. For certification, reject wrong-kind, forged, stale or non-independent
   receipts; incomplete case/input coverage; changed scope/history;
   active/deferred swaps; and cross-ticket/protocol reuse. Removing authority
   must remove certification. Preserve audited lifecycle writes without
   excluding any execution input from freshness checks.
4. Independently review the contract and implementation. If templates change,
   regenerate and verify their derived surfaces. Run relevant lint/types,
   acceptance and final full tests/CI on the implementation candidate once.
5. Only after separately authorized integration/deployment, obtain the fixed
   authenticated observation, complete typed certification and trusted installed
   closing proof. Selected reruns, qualification matrices and branch review
   cannot substitute for that proof.

No paid qualification starts here. Historical failures stay unchanged. Failed or
unavailable certification leaves recovery unavailable; no waiver is inferred.
Dependency audit policy, model admission and existing review gates are unchanged.
