# Codex portable loading proof boundary

This binds the Codex example of the accepted portable-package scenario. The
complete candidate comes from the unchanged production Codex generator, using
its isolated-output option and explicit --portable-core pilot selector. Existing
custom-output callers retain the legacy projection. At the revised RED boundary,
the selector is accepted but not yet wired to the portable writer; native
readback must expose that missing integration. The fixture never inserts or repairs a root manifest.
It replaces one existing workflow and a referenced guide with unpredictable
resource markers, and changes only the compatibility overlay's interface label
to a unique decoy. These mutations test resource loading and extension selection;
they do not implement the missing portable format or claim shipped-byte proof.

The exact 0.160.0 binary installs the full candidate through its actual local
marketplace. Native JSON installation output identifies the actual isolated
cache, whose complete file set and bytes must equal the candidate before the
turn. Its public app-server plugin/read endpoint exposes the interface
it selected. A separate native read-only Agent turn invokes the installed skill,
reads its packaged guide, and returns both unpredictable markers. No hook trust
or sandbox bypass is granted. The source guide is absent from the scratch project.
Authentication comes only from an explicitly provisioned isolated test profile;
its contents and generated private profile are never review targets/context.

The intended failure is actual native selection of the conflicting compatibility
interface when the production root/OpenAI extension should supply the original
interface. Setup, API rejection, authentication failure and resource failures
cannot produce CODEX_COMPATIBILITY_OVERLAY_FALLBACK. That literal is raised only
after both real resources loaded and native readback is compared with the expected
production interface captured before the decoy mutation. Root-format capability
was separately established on this exact binary; the production projection must
now earn it. The primary proof does not infer enforcement from content loading.
The required runner remains incomplete until separate native guard, activation,
shipped-carrier and other accepted obligations exist.
