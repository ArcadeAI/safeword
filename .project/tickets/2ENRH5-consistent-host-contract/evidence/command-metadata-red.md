# One canonical command purpose across delivery projections

Supporting build/install component for Scenario: One shared skill change reaches
every applicable agent. This is not native host loading/conformance or full
scenario proof. Required exact-host/resource cases and all remaining metadata
flags remain separate accepted obligations.

Three independently owned repository fixtures each change only the canonical
bdd SKILL.md description to a unique marker; workflow body and other metadata
values are preserved. The When exercises actual developer/public entrypoints:
OpenCode V1 CLI install with an owned profile, actual OpenCode V2 package
generator, and actual Cursor wrapper generator followed by public legacy CLI
install. No shared-policy or metadata result is mocked. Installation is offline
and skips dependency downloads, using read-only node_modules/current built
dispatcher links. Actor processes inherit the repository-pinned toolchain; they
do not trust a copied mise config or change user tool settings.

Each resulting installed/generated SKILL.md must contain its unique marker
before the command metadata assertion. All three actors succeed and load the
changed root, then fail because command descriptions still come from a separate
authored table. COMMAND_METADATA_OWNER_DRIFT is printed only by that final
assertion. Author run /tmp/safeword-command-metadata-red.log: three intended
failures, no setup/import/CLI errors. Fixture/profile/package writes and cleanup
remain below exact owned temporary parents; no global profile or credential use.

The shared command contract must own workflow references while purpose comes
from actual canonical skill metadata at the caller's templates root. Host
renderers should translate reference/format only. A module-load filesystem read
or global default metadata root would break synthetic root variation and
minimal runtime carriers; keep metadata reads explicit at generation/install.
No production metadata consolidation has been implemented before this review.

The final GREEN also requires each actual delivery's public command names to
match the independently discovered canonical command source population (18
current template entrypoints). The current OpenCode table covers only12; the
shared contract must not preserve that incomplete host-private subset or hide
canonical wrappers. Cursor's existing18 references remain available. This is
accepted full-content graph/parity work, not new workflow behavior. The initial
RED still fails first at the stale purpose after all actors loaded the marker;
exact command population becomes an additional discriminating GREEN condition.
