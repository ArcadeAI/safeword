## Implementation

The portable core writer emits a private catalogue.json companion containing
name, description, relative file path and body offset. It indexes actual rendered
bytes through the existing canonical frontmatter parser. Every normal render,
including a canonical revision in the shared probe, refreshes that index.
Workflow text remains in the single packaged SKILL.md. The companion is internal
registration metadata, not an invented Agent Plugins standard field.

The SDK reads those files and calls the exact target's Skill.Info constructors
and ctx.skill.transform. Path uses the SDK's branded path constructor; the
documentation's raw-string example does not satisfy its strict TypeScript type.
No YAML parser or Effect implementation is bundled into the SDK entry. No new
dependency or copied upstream code is introduced. JSON metadata is trusted
package content, not an untrusted client input.

openCodeWorkflowName is the single public-name projection for the preserved V1
renderer and V2 registration. Canonical explain maps to safeword-explain in both
versions. V1 rendered output tests pass. The independent proof retains the
public name as its expected contract rather than accepting any implementation
name, and missing-workflow diagnostics include the actual native tool result.
