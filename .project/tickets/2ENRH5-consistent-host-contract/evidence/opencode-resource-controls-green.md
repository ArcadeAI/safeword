# Native OpenCode resource and rejection controls

PR 2 component review, not customer admission or whole-feature verification.
Review angles: actual native failure-state observation; V1 resource/runtime
provenance; Bun executable resolution and isolation; accidental duplicated
authoring or weakened assertions. Currency: 2026-10-21 from the host-provided
date. These proof fixtures use the accepted exact Bun and OpenCode targets;
current product versions are not substitutes for those targets.

## Required registration

The fixture copies the generated V2 package and changes only one required
worker's allowed tool to UnavailableFixtureTool. The actual SDK package setup
cannot represent that tool restriction and throws the adapter's existing
explicit error. The independent native observer sees the actual attempted
shell call and candidate plugin state. Both native runtimes must report the
candidate non-active, with the exact worker/tool cause. Native rollback removes
the failed package's registrations; an ordinary control write must actually run.
This proves unavailable native activation, not an SDK schema rejection or a
public Safeword status/admission implementation. No production change was
needed for this already-correct behavior. CLI/TUI pass in
/tmp/safeword-opencode-required-registration.log, roots HsI7tL / XcSVLI.

## Retained V1 resources

The common canonical catalogue fixture creates the same unique workflow,
guide and helper markers used for other host resource proofs. The actual V1
catalogue generator and profile reconciler install that fixture's canonical
content into the owned native profile; no native command body or policy is
stubbed. Fixture project fallback resources are removed. The real V1 skill
tool must load the profile workflow; the scripted model derives the guide path
and exact helper block only from that native tool result. The native read and
bash tools then execute both. CLI/TUI pass in
/tmp/safeword-opencode-v1-catalogue.log, roots CfxVAe / qn97Vt.

V1's production version-qualified bunx binding is unchanged. Current Bun docs
and source establish that version-qualified execution bypasses local binaries,
so merely installing a local node_modules package would test the wrong source.
A fixture-only loopback registry serves an actual tar archive of the generated
portable runtime/templates, with a minimal executable carrier manifest. This
is a resource-binding carrier, not npm release/manifest evidence. The real Bun
client fetches it into fresh owned TMPDIR/BUN_INSTALL/cache directories. The
server closes before the native host turn; the unchanged bunx command resolves
its real freshly installed cache. Runtime bytes and the entire templates tree
must match the generated source. No cache entries are hand-authored, no package
is published, and no existing cache/profile is changed. A real helper readiness
check runs first and its artifact is removed before the native action. GREEN
requires the actual helper artifact to identify the installed candidate's
runtime and template, alongside all three observed markers.

The supplementary model factory can return environment values for only its
owned native child. Its existing default environment remains unchanged. This
allows the isolated official Bun installation to be reused by the actual bash
tool without changing the workflow command or repairing its runtime path.

## Runner and limits

The native-opencode group invokes every existing worker/optional/command probe
plus required-registration and V1 resource probes. It may return zero only
when all six feature rows and all supplemental native cases pass. A zero here
covers this PR 2 execution group; sealed package admission, public status,
collision handling, lifecycle recovery, full inventory consolidation and final
all-host verification remain required by the accepted later slices. The old
unconditional incomplete exit is removed because its named native controls
are now executable. No scenario ledger checkbox is changed.

Applicable principles: structure enforces through actual native/tool/artifact
observations; add-never-replace through preserved V1 production delivery and
owned fixtures; smallest complete mechanism through a zero-dependency temporary
registry rather than a second production runtime binding. This component does
not establish NTB/TBU experiential acceptance or other agent surface parity.
