# Discover remaining native handler registration families

Supporting repository boundary component for Scenario: Coverage includes every
supported host without an author checklist. This component discovers actual
native registrations; runtime-lane dispositions and all native conformance
remain separate accepted obligations and cannot be inferred from it.

The real checker in a fresh owned repository reports missing_handler_inventory
for Codex and OpenCode. The new primary proof requires no such omissions, and
compares exact event multisets for three independently traced current producers:
Codex's native hooks.json (five events), the V1 plugin callback object plus its
two event-bus dispatch cases (six facets), and V2 Plugin.setup plus all seven
SDK hook/transform call sites. The two skill transforms and two prompt hooks
remain distinct; collapsing them would fail cardinality. Expected events were
read directly from actual native manifest and adapter source, not generated by
the production discovery under test.

The When is check-host-contract.ts --json, not an injected discovery function.
Current output names both omitted adapters and fails at the intended assertion
NATIVE_HANDLER_INVENTORY_MISSING. Existing unrelated owner/classification errors
are permitted, but cannot satisfy the exact native family assertions. No native
discovery or new registry declarations have been implemented before RED review.

Implementation stays in the existing integration registry for production source
declarations. Static callback extraction uses installed TypeScript5.9.3 in the
repository checker only; do not import the compiler into a shipped runtime.
Read actual command manifests, generated V1 callback text and V2 source instead
of a second event catalogue. Source classification remains explicitly incomplete
until shared bindings and lane dispositions cover every discovered facet.
Primary reference fetched this session:
https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API
The official API guide covers this installed pre7 compiler. No dependency change
or new universal execution runtime is needed.

Discriminating source-change controls are included before implementation:
append a second actual Stop registration in the owned Codex manifest, and a
second valid execute.before SDK hook in V2's real setup method. The next real
check must discover both extra registrations, preserving multiplicity. Restore
both source files byte-for-byte and require the original exact event multisets
again. These controls rule out a checker returning a fixed native event table.
No unrecognized SDK event or fake native execution result is introduced.
